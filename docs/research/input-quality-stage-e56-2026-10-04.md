# E56：在 Sense 现有候选上验证完整静态词级语言模型

## 结论与发布边界

固定词级三元模型、单标量校准，在两个已知开发集和三个既有回归集上均改善首选、前五和字错数；
保留所有退步。**满足进入 Android 原型的主机门槛，尚未接入 Android，不进入 v0.4.16 正式版。**
本轮没有修改生产解码器、模型资产、个人词库或 UI。整体输入质量目标继续。

## 实现

- 使用已固定的 libime 1.0.11 静态模型读取器和 `zh_CN.lm`，而非 E14 的整套旧拼音引擎。
- 模型 SHA-256：`3588b3942c8fd62e1a6bd3bae8c7cadc0faf928c175b245224ed475862218387`。
- 将末尾上下文与候选文本一起构造词格，词长 1–8 个汉字，总长最多 26 个汉字。
- 动态规划仅合并最近两个词 ID 和历史长度相同的状态；不使用 beam 裁剪；同分按词路径字节序确定。
- 使用 null 初始状态、不加 EOS，未知词使用模型原始概率；任何受评候选含未知词时整个候选组保持原序。
- 原有来源与个性化保护先于评分。原始候选、词频得分和召回范围保持，不利用参考答案生成模型请求。
- 组内中心化词概率，按候选汉字长度平方根归一化，残差有界为 ±8；只校准一个 `[0, 4]` 标量。
- 6,146 组中 32 组因未知词跳过，6,114 组 / 48,345 行参与拟合。固定正则 0.001，最终权重
  `1.561699116266376`，8 次迭代收敛。开发集打开前冻结权重，回归不再拟合。

## 正确性与成本

- 10 项 Python 工具测试通过。
- 3,280 组人工小词格逐路径穷举与动态规划相同；另覆盖非法 UTF-8、非汉字、长度和补充平面未知字。
- 真实模型前 256 个符合长度约束的固定校准请求：3,515 条完整路径穷举，分数和路径精确一致。
- 独立脚本重新计算 1,006 个状态、6,502 个值，最大误差为 0；821 组评分，185 组保护保持。
- 每组评价另启进程重复执行，除时钟数值外输出一致；路径再次直接评分相同。
- 单组额外主机成本代理 P95：开发集 0.5113/0.4732 ms，三个回归集 0.6508/0.5457/0.6225 ms。
  该代理相加原生候选评分计时与 Python 重排计时，排除模型加载、IPC/JNI、原解码器、渲染和上屏；
  **不是 Android 端到端性能**。原始二进制及大模型保留在本地 E/G 盘，不作为 Android 资产提交。
- 最初真实模型校验的内联 shell 引号问题和回归脚本参数前缀问题均在模型评价前失败，日志保留；
  改用独立 shell 文件及检查后的启动参数，新增参数测试。没有因质量结果改变算法或重选权重。

## 模型许可与下一步

上游固定提交的 [REUSE.toml](https://github.com/fcitx/libime/blob/171edcf137001e8eb8274f53ec010058cda70b09/REUSE.toml)
明确将 `data/lm_sc.**.tar.**` 标记为 CSSlayer 2022–2026、LGPL-2.1-or-later。
`verify_static_word_lm_source.py` 验证匹配本次归档文件名、原始归档/ARPA 摘要以及上游 CMake 固定摘要。
Debian 1.1.17 的版权更新提供旁证；只检查 dsc 中归档大小/摘要，未声称验证 PGP 签名。
早先 decision 文件的 `modelRightsReviewComplete: false` 保留评价当时状态，
后续 `model-license-verification.json` 记录显式许可已确认、Android 打包尚未完成。

下一阶段仍需：Android 原生读取器与 ABI/端序验证、模型源与转换配方及依赖许可随包交付、
加载/内存/取消和 IME 生命周期实测、查询级个人证据传递、真实编辑框续打回归。
主机个人证据来自聚合特征，仍需解决生产路径中相互抵消的可观测性问题；不把诊断观察器默认启用。
用户要求先正式发布并准备设置页改版，故本轮止于可复核原型，后续接入另行提交。
