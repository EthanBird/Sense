# E55：分词对齐与正负搭配分的实际候选对照

## 结论

已实现固定分词、带负向回退的词搭配评分，以及个人词路径的离线保护；完成真实校准和两域回放。
**唯一待采用模型 aligned-signed 未通过质量门槛，不接入 Android，不产生新 APK。**
四个固定对照都没有同时改善两域，不在看完结果后换选对照或继续扫系数。
原输入质量目标保持；本轮结束的是这条小语料搭配残差试验，不是整体优化任务。

## 实际改动

- `aligned_word_context.py`：从 E54 训练分词路径提取 55,622 个词/单字，保留原 607,457 词分词器的
  浮点分数、未知字分数及最长优先同分规则，不重新归一化。序列化后全部 85,502 条背景路径逐一一致。
- 两种分词（原解码路径/固定重新分词）×两种分数（仅正向/正负向），其余规则相同。
  保留词对的有符号对数似然比截到 `[-4,4]`；已知上下文下未见词对使用 `log(backoff)`，未知上下文为零。
  CW 仍只用原来精确的至多两字前文，未混入另一项后缀回退改动。没有 BOS/EOS 新奖励。
- `run_e55_aligned_context.py`：使用已有真实候选，固定四组训练，先冻结所有标量再读开发排名。
  记录完整排序、前五退步、字错误、整句/中点上下文分层和主机额外耗时。
- `audit_e55_scores.py`：不调用新评分器，用独立端点遍历分词和从计数重建概率，复核 1,024 个状态、
  6,764 个实际分数及每组指标，最大分数差 0。1,024 是四组×两域×128，非 1,024 个独立句子。

分词器 1,855,296 bytes，加 E54 计数表共 14,506,002 bytes，通过预设 16 MiB 主机 JSON 上限。
这不代表手机反序列化内存或 JNI/Kotlin 集成成本已验证。

## 数据与个人词保护

原样复用 E54 的 71,154 条来源隔离背景记录和 136,206 个保留词对；不增加语料，不改计数阈值。
逐句 Tatoeba CC-BY-2.0-FR 署名、词典 GPL-3.0 说明、全体 4,094 校准来源族的排除都由 E54 证据继承。
分词器词表只由背景文本产生，不使用开发文本/参考答案。

E53 的 6,146 个校准状态、48,599 个候选仍来自当前生产代码；重新核对源码、资产、原始导出及来源族。
完整原始导出再给每个胜出路径附上 personalEvidence，实际此批为空用户库，个人路径为零。
拟合均只使用一个 `[0,4]` 标量、相同 CE/ridge 和八点 tanh 上限，没有新先验系数。

新保护解决的是**离线原型**的缺口：`BASE_COMPOSED` 也可能带有个人分数。
任一可重排候选出现 PERSONAL_BASE/FLOOR/ADJUSTMENT 非零或个人专属空权重词边时，整个列表保留原次序、
不调用新评分器；缺少明确来源标志也保留原次序。测试覆盖正负调整及不同分量和为零，原守卫会调用评分器而新守卫退出。
但旧诊断导出没保存每条已知词的个性化身份，同一分量里正负完全抵消可能不可观察。
未来 Android 接入必须有显式路径来源，而非把主机诊断 observer 开到生产来充当保证。
因此本轮不声称修复了线上个人词问题，也不声称这些合成保护测试替代了真实学习生命周期测试。

固定重新分词能重现训练全文边界，但中点截断只有两字前文，候选仍独立分词；它不保证与训练全文切口边界等价。
旧字符 LM 原本使用完整 Tatoeba train；隔离是针对新增计数和本次校准，不是整个输入法从未见过校准语料。

## 固定训练结果

训练基线首选 4,963 / 6,146，前五 6,034，字符错误 1,583。

| 变体 | 标量 | 校准首选 | 校准前五 | 校准字错误 |
|---|---:|---:|---:|---:|
| 原路径 / 正向 | 1.296169 | 4,972 | 6,037 | 1,579 |
| 对齐 / 正向 | 1.282483 | 4,967 | 6,036 | 1,563 |
| 原路径 / 正负 | 1.174622 | 4,974 | 6,039 | 1,581 |
| 对齐 / 正负（唯一候选） | 1.217250 | 4,948 | 6,034 | 1,593 |

四组均收敛，零残差与原始分数精确一致。CE 收敛不是首选准确率提高，训练集同样显示这一差别。

## 已知开发域实际排序

每域 64 个来源句，分别整句与 oracle 中点前文，共 128 个相关状态；不是新盲测。

| 变体 | 新闻首选 / 前五 / 字错误 | 日常首选 / 前五 / 字错误 |
|---|---|---|
| 原基线 | 65 / 97 / 142 | 83 / 113 / 70 |
| 原路径 / 正向 | 62 / 97 / 148 | 83 / 116 / 68 |
| 对齐 / 正向 | 62 / 97 / 149 | 82 / 116 / 70 |
| 原路径 / 正负 | 63 / 97 / 144 | 84 / 114 / 67 |
| 对齐 / 正负（唯一候选） | **62 / 96 / 145** | **83 / 114 / 70** |

每组候选成员及召回完全保持（新闻 118、日常 121）；排序确定性复跑一致。
对齐/正负使有区分度的特征状态从正向对照的 12/43 升至 111/99，但首选未提升：
**更多非零/不同特征不是更好的语言判断。**

唯一候选的整句首选：新闻 29→28，日常 40→39；中点：新闻 36→34，日常 43→44。
新闻有 2 个首选改善、5 个损失，日常各 3 个；所有逐条记录在 evidence 的 comparison/details 中。
改善如“演讲是表示→演讲时表示”“一堆双胞胎男孩→一对双胞胎男孩”；
损失含“出厂价→出厂家”“谁是傻瓜→水是傻瓜”“高于农村→高愚弄村”。
日常一条参考“道本语”属于来源术语；他/她等参考歧义继续原样保留，不事后修标签来抹掉得失。

唯一候选的额外 Python 评分 P95：新闻 0.6706 ms、日常 0.5864 ms。
它不包含原解码或 Android UI；本轮没有证明手机 100 ms 达标。

## 检查、失败与下一步

新增 23 项测试；相关工具最终 **68 项通过**。最初实现前有模块尚不存在的导入失败；一次测试命令写错模块名，
保留错误日志后更正为实际 `test_train_association_model` 并全量重跑，未把这两次错误记为产品回归或通过。
独立评分审计通过，冻结源文件/策略/输入在运行末尾一致；默认代码、模型资产与已有 APK 保持。

E54 的边界和负向证据缺口确实可修，但 E55 排名否定了“修完这些就能提升默认质量”的假设。
当前 PMI 式搭配残差仍依赖很小的背景统计和原词频，不是完整词级语言概率；负向回退甚至可能推高错误分词。
停止这条局部调权路线，不把更多审计或扩大覆盖当作用户输入质量改善。

已回查 E14：成熟 libime 1.0.11 加新数据的整引擎替换也有损失，**不重复该旧对照、不直接换掉 Sense 前端**。
下一切片优先试“成熟静态词 LM 对 Sense 真实候选的词格打分”：使用完整词级概率和可延续 LM 状态，
与此前小样本 PMI/旧整引擎替换区分；先验证分词得分、未知词、原个人词保护及固定候选回放，
再考虑原生后端和跨按键状态复用。上游模型训练来源/分发说明仍需独立厘清，尚未成为 APK 资产。

参考实现：[libime 固定源码](https://github.com/fcitx/libime/blob/171edcf137001e8eb8274f53ec010058cda70b09/src/libime/core/languagemodel.cpp)，
[固定模型构建清单](https://github.com/fcitx/libime/blob/171edcf137001e8eb8274f53ec010058cda70b09/data/CMakeLists.txt)。
本轮在线复核构建清单仍指定 E14 已下载的 20260629 模型；不是声称新上游引擎已本地编译。

复现：先按 E53/E54 清单还原依赖（大原始导出本地保留且有摘要），再执行：

```powershell
$env:PYTHONPATH='tools'; $env:PYTHONUTF8='1'
python tools/run_e55_aligned_context.py ROOT NEW_OUTPUT_DIRECTORY
python tools/audit_e55_scores.py ROOT NEW_OUTPUT_DIRECTORY
```

NEW_OUTPUT_DIRECTORY 与 e53/e54/e44 放在同一输出根目录下，必须预先创建；工具使用写新文件方式保留旧结果。
证据入口：`benchmarks/results/e55-evidence-manifest.json`、`e55-acceptance-gate.json`。
