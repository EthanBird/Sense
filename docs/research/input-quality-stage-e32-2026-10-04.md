# E32：Android 大个人词库的真实输入与持久化验收

## 结论

补齐此前只有主机 JVM 证据的容量链路：专用 API 37 x86_64 模拟器上，
固定 1,000 / 10,000 / 10,000 / 1,000 条 SQLite 个人词库，
**56 次系统触摸确认、4 次真实 IME 进程重启全部通过**。
两种规模中，目标词默认复用的计数均已持久化，全部种子记录与上下文映射保留，
无关词条逐字段未变。没有更改产品代码、词库、模型或 rc.3 APK。

本轮新增独立 Android fixture、可重复种库/采集工具及 4 项工具测试。
工具套件最终执行 443 项：442 通过、1 项既有 Windows 符号链接权限测试跳过。
不把之前的 943 项产品测试冒充本轮重新执行。

## 覆盖方法

- 固定 rc.3 Debug APK 摘要，校验实际安装 APK；只接受 `sense-input-quality` 专用模拟器。
- 每块只重置 `io.github.ethanbird.senseime.debug` 的合成测试数据，拒绝实体设备和既有输出目录。
- 直接复用生产源码的 SQLite v4 表结构；合成拼音/汉字三元组来自已有 M9 容量规则，
  每条具有 8 个上下文。另含程彻、智能体、权力/权利和明确选择的上下文及别名。
- `adb push` 完整传输后在设备内通过管道交给 debug UID，安装前后校验数据库 SHA。
- 原生产 `PersistentUserLexicon` 在实际 IME 进程中加载这些行；没有在测试 APK 里另建 decoder 代替。
- 七个固定输入为程彻、智能体、人民→权力（别名 `qvanli`）、获得→权利，
  以及合成表的头/中/尾三个词。前后两次均用 32 ms 目标节奏的真实 shell 触摸。
- 逐键检查外部编辑框中的全部原文前缀，确认文本、组合结束及下发触摸收据；
  写入者是 Sense 的实际 InputConnection，不是测试宿主直接填写答案。
- 进程重启时先切回原输入法，再停止 Sense，确认 PID 消失；重新选择后必须得到不同 PID。
- 停止进程后捕获 SQLite 主库、WAL 和 SHM，原始副本保留；在分析副本上校验完整性、
  行身份全集、所有上下文映射，以及七个抽样词两次默认接受均增加 use_count。
- 每轮完成或失败都保留；结束时清除调试版合成大词库并恢复原 Gboard 和硬键盘偏好。

## 观测，不作全场景性能承诺

最终四块实际按键间隔中位数均为 33 ms，P95 为 37 / 38 / 35 / 36 ms。

| 个人词条 | 确认数 | 空格触摸至外部编辑框中位数 | 观测 P95 | 最大值 |
|---|---:|---:|---:|---:|
| 1,000 | 28 | 69.5 ms | 136 ms | 164 ms |
| 10,000 | 28 | 70.5 ms | 126 ms | 163 ms |

这是**七个短的已记忆词**，不同于 E31 八组普通/长句负载；两表数字不横向比较。
较大词库 P95 较低不表示“词越多越快”，小样本、查询顺序和 ART 状态都有影响。
没有根据耗时决定重跑，也没有在本轮做产品优化或调参。

重新选择 IME 到轮询观察到模型就绪：

- 1,000 条：3,595 / 3,804 ms；
- 10,000 条：5,185 / 5,195 ms。

这一段包含系统切换、shell 命令、UI 显示、全部生产资源装载和观察间隔，
**不是 SQLite 独占耗时，更不是键盘首帧或每键延迟**。
它指出下一处需要分解的成本：大个人词库恢复和索引建立，而非再扫描热解码常数。

## 设备运行失败与工具修正

1. 第一组四块在种库 SHA 门槛停止，没有进入产品测试。
   独立探针证实 Windows 主机经 `adb shell` 标准输入传递 323,584 字节时，
   成功退出却只写入了原内容的 7,959 字节前缀；当时 IME PID 为空。
   改用 push + 设备内管道后，逐字节回读相同。该结论只描述本机观察，非所有 adb 的通则。
2. 第二组已有三块完整通过；另一块完成第一阶段 7 次确认后，
   停在“进程应已停止”前置断言，后半阶段没有执行。
   初版宿主先检查计数，因而给出了“缺少两次持久化”的间接错误；
   原 instrumentation 明确是 `ExternalEditorCapacityTest.kt:93` 的停止状态断言。
   49 次已执行的确认全通过，这不是已复现的丢词。
3. 测试重启改为先取消 Sense 选中状态，避免隐藏键盘后仍绑定的服务与停进程竞态；
   保留原等待期限，不增加睡眠“碰运气”。宿主先检查阶段/重启覆盖，再判定持久化。
   修订后的四块全跑，不择取第二组的成功样本拼成结论。

两个失败组、传输探针、旧/新工具源码、各自 SHA 与最终全部结果都在证据索引中。
第一次开发工具测试还修正了 Python SQLite 上下文退出不关闭连接的问题，
使用显式 `closing`，避免 Windows 临时文件仍被占用。

## 本轮没有证明的内容

- 自然用户词库分布、自然聊天输入准确率、所有 10,000 行都在 UI 中逐一检索；
- 触顶后新增词条的淘汰交互和导入超额词库；
- 独立 SQLite / 内存索引构建成本、实体手机或其他 Android/厂商版本；
- 渲染首帧、全部输入稳定 100 ms，或总体质量专项已完成。

无关行校验覆盖整个持久化表，UI 检索只覆盖上述固定样本，这两类证据分开解释。

## 复现

先构建独立 `input-quality-device` fixture，安装触摸 helper，保留 rc.3 Debug APK。
在专用 AVD 选择 Gboard 后，运行：

```powershell
python tools/measure_personal_dictionary_android.py .artifacts/input-quality/NEW_RUN
```

`NEW_RUN` 必须全新。种子数据、生产表定义 SHA、APK SHA、输入收据、失败和 SQLite 原始日志均随运行保存。
结果索引：`benchmarks/results/e32-acceptance-gate.json`、`e32-evidence-manifest.json`。
