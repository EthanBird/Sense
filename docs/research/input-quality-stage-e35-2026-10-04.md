# E35：在当前输入链重新检查冻结四元模型

## 决定

**短码阻塞已解除，成本阻塞仍在；不切换默认模型。** rc.4 正式签名 APK 和全部生产输入代码保持不变。
这不是再次运行相同失败产物挑一次较快的结果：E18 之后已加入 E19–E23 的补全评分、
来源保护及末音节覆盖，E27/E34 加入搜索复用；本轮固定当前实现和 E18 原模型，重新检查它们组合后的行为。

运行前固定 `benchmarks/corpus/e35-fourgram-reassessment-policy.json`：只比较原三元与既有
balanced-fourgram，不训练、不调折扣/权重/预算，不读取新的测试集。
所有来源回放和短码探针均为已用回归集，不称新的独立准确率。

## 短码与个人词：原阻塞解除

同一个已接纳 E34 核心 JAR：1,468 个输入/上下文/限额配对状态，2,936 次完整结果重复一致。
其中 1–3 字母共有 1,188 个状态，**全部首选文本一致**。四种 `wox` 状态仍以“我想”为首选，
不再被“我想和你在一起”抢位。

这不等于所有候选相同：短码完整结果相同 995/1,188，总体相同 1,062/1,468。
所有变动的前五候选均在原始记录中。两种模型的“程彻”“智能体”显式学习、默认接受和
内存快照重建共 12 项断言通过，不冒充新的 SQLite/进程重启/隐私测试。

旧 Java 工具使用的学习证据构造器已跟不上 E29 的上下文字段，本轮补入空上下文参数，
不改变原探针的学习语义。Android library 测试增加受限 runName，保留旧 E18 输出而不是覆盖。

## “类／累”未解决的原因

E28 三组诊断的六个状态仍为首选 4/6。“今天有一点累”依然第二，带上文“天有”的“一点累”仍第三。
此前真实评分已表明字词先验压过模型偏好，本轮没有添加例句特判。

只读冻结二进制进一步得到：`有一点` 是保留的三字上下文，但后继“累”和“类”均没有直接四元条目。
二者都回退到原三元条件概率，并加同一个 −0.4128452 回退对数权重：

| 后继 | 原三元 log P | 扩展 log P |
|---|---:|---:|
| 累 | −7.3434407 | −7.7562859 |
| 类 | −11.8889476 | −12.3017928 |

这是二进制概率的 float64 诊断，不是完整词格 Float 总分。生产 LM 特征另有 +6、截断和归一化，
所以不把相同概率回退量直接视为最终得分的完全抵消。
这一例子表明：增加模型阶数并未补到所需的直接证据；后续应检查词频先验和语境特征的校准，
以及共享回退经截断后的影响，而不是继续对同一模型调高全局权重。

## Android ART：成本门槛仍失败

只使用专用 API 37 x86_64 模拟器的 library instrumentation，不切换用户输入法、不操作实体手机。
当前代码下两个模型共享不可变词库，原 E18 八条输入、相同预热及 ABBA，每查询每模型 8 次，共 128 次。
所有结果与各自参考完整相等，1 项 instrumentation 通过；实际输入法 APK 和系统默认 IME 前后摘要/身份不变。
这是进程内调用，不是键盘触摸到编辑框的时延，不与 E34 的 129.5 ms 指标混用。

| 指标 | 原三元 | 四元扩展 |
|---|---:|---:|
| 混合 64 次中位数 | 24.97 ms | 25.53 ms |
| nearest-rank P95 | 169.22 ms | 196.41 ms |
| 最大值 | 177.42 ms | 218.53 ms |
| 最长句中位数 | 161.13 ms | 189.24 ms |
| 后三次加载中位数（不含 I/O） | 50.13 ms | 135.89 ms |
| 估算常驻数组 | 3,090,904 B | 6,072,092 B |

预先冻结的混合中位数/P95 不增加门槛未过；不重跑同一产物选择较好结果。
8 个查询中 7 个中位数增加，只有 `wox` 降低；各查询全部分位数保留。
首次加载受类加载/JIT影响，不把四元首次更快解释为冷启动改善。数组估算不包含所有对象或进程 PSS。
