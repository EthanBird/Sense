# D7：触摸优先的联想生命周期

## 本轮发现

上一轮 E3 是纠错搜索改进。本轮检查真实系统输入法的联想交互，不调整词库、LM、拼音搜索或排序。

已有逻辑在成功上屏后等待 420 ms，再用联想词替换工具栏；闲置 4,500 ms 后恢复工具栏，右侧有关闭按钮。问题不是缺少计时器，而是**固定计时器忽略了正在进行的手势**。

在专用 API 37 模拟器上，通过外部编辑框输入 `nihao` 并确认“你好”，等待正式联想出现，按住一个真实候选超过 4.5 秒：

- E3 原包清空了手指下的候选；断言 `Idle expiry must not remove the word being touched` 失败。
- 松手时，旧目标已失效，词也没有提交。它没有写错位置，但会吞掉用户的点选意图。
- 保留失败日志与截图，而非直接从源代码猜测原因。

## 修复

### 状态与计时

| 事件 | 行为 |
|---|---|
| 成功提交中文 | 原有 420 ms 延迟唤起保持 |
| 继续键入、主动关闭、切换编辑框或隐藏键盘 | 取消本轮显示与旧回调 |
| 第一根手指触到候选／联想栏 | 暂停闲置收起，作废原计时票据 |
| 手指横向拖动、点选高亮消失 | 仍属于正在交互，保留联想栏 |
| 最后一根手指离开 | 对仍显示的同一轮联想重新计算 4,500 ms 闲置时间 |
| 取消事件或候选批次被替换 | 释放旧触摸归属；旧松手不选择新批次 |
| 旧计时回调迟到 | 票据不匹配，忽略 |

`CandidatePointerActivity` 单独记录物理指针归属，不从“当前高亮了哪个候选”推断交互状态。实际开始滚动时，高亮本来就会清除；把两者混为一谈会让拖动再次触发原问题。

UI 只在第一根指针进入／最后一根离开时向 service 通知布尔状态，不在每个 MOVE 帧上传文本或发消息。`AssociationDisplayLifecycle` 保持主线程管理，交互开始／结束会更新代次；已隐藏、取消或进入新一轮等待的状态不会因旧手势结束而复活。

既有候选 revision、编辑器会话、InputConnection 身份和前文一致性校验保留。联想从未被自动提交到外部输入框，点选之外仍以用户输入为准。

## 真实路径回归

新增 8 项外部编辑器测试，真实触摸经过系统 IME，没有直接调用 Sense service，也没有向个人词数据库预填记录：

1. 按住联想跨过旧期限，松手后把原候选准确提交一次。
2. 上屏后立即继续拼写，旧联想延迟回调被取消；新词提交后可以再出现。
3. 关闭后保持关闭，直到下一次成功提交；新联想可通过无障碍候选动作提交。
4. 完全不操作时自动收起，不改动编辑框正文。
5. 横向手势跨过旧期限仍保持显示，松手不误选词，之后重新闲置收起。
6. 按住旧候选期间，宿主切到另一输入框；松手不向任一编辑框写入旧联想。
7. 隐藏再打开键盘，旧联想不复活。
8. 切到密码框，移除旧联想并按字面输入。

系统 fixture 的 8 个静态单字建议可能全部容纳在一行，因此第 5 项证明的是横向触摸／取消点选的生命周期，不单凭它宣称发生了可滚动内容位移。另加真实 Android View 测试，以 20 条候选制造溢出，**断言实际滚动偏移大于零**，再验证触摸归属、候选重新发布、CANCEL 和下一次正确选择。

- `tools/test_external_editor.ps1 -Association`：仅面向专用模拟器运行此组测试；支持单数／复数 instrumentation 结果校验。

## 证据边界与下一步

- 最初单例的失败证据与后续两次八项通过均保留。验收统计仅使用最后构建的测试 APK 对应结果，不混用不同产物。
- 查看了真实联想截图：联想行独占工具栏区域、右侧有关闭按钮，键盘几何未跳动。触摸期间保持显示的截图另行留存。
- 本轮没有重跑语料选参或报告新的算法准确率。core 解码源码与词库／模型资产已经逐项与 E3 哈希对照；E3 性能数字不当作新 APK 的重新测量。
- **联想内容质量仍待改进**：当前是个人历史词＋词库字符 bigram；例如“你好”之后会出现“的、了、好”等单字，这不等于理解整段上下文。本轮解决生命周期，不把它包装成智能联想质量完成。
- 下一步重点是让已有上下文 LM 提供更自然的后续词证据，并减少低信息量建议触发的界面打扰；另外仍需横屏、大字体、系统辅助功能超时偏好与更多宿主场景。

整体输入质量目标保持进行中，本阶段未 commit、push 或 release。
