# E12：真实候选路径记账，为监督排序建立可信输入

状态：本轮完成得分观测切片；没有训练或启用新的排序权重。输入质量总目标继续推进。

## 为什么先做这一层

E11 的搭配竞争规则通过开发集、却在独立测试退步，已经撤回。本轮保留当前词库、
LM、beam、纠错预算和默认分数，把得分实际来自哪里记录清楚，而不是再追加逐词规则。

- Och 的工作强调训练目标与最终任务质量可能不一致。对 Sense 的工程启发是：
  更低的 LM 困惑度、分数更漂亮，都应再接受最终候选与上屏评估；本轮没有复现 MERT。
  [原论文](https://aclanthology.org/P03-1021.pdf)
- Collins、Koo 研究基础模型先生成候选，再由另一模型重排的框架。Sense 下一步先冻结
  候选池，区分搜索漏召回与排序失误；这是本项目的应用推论，不借用其解析任务指标。
  [原论文](https://aclanthology.org/J05-1003.pdf)
- Zhang、Wei、Zhao 研究从用户实际选择中调整词的使用可能性。Sense 继续保留个人词与
  明确选择反馈的独立地位，没有用通用 LM 取代用户确认。
  [原论文摘要](https://arxiv.org/abs/1712.04158)

## 实现范围

新增 `PinyinScoreDiagnostics`、`M19ScoreFeatureBenchmark` 和独立 Python 审计器。

| 分项 | 实际来源 |
|---|---|
| LOG_FREQUENCY | 读取 SPLX 时的 `log(weight + 1)`；这是词库权重，不等于真实语料词频的无偏估计 |
| FALLBACK_TIER | 实际基础/覆盖层惩罚，词边同时带 tier 与原始 weight |
| UNIGRAM_MASS / NORMALIZATION_ANCHOR | 词格累加与导出时的质量项、归一化锚点 |
| INTERNAL_BIGRAM / WORD_BOUNDARY | 实际选中词边之间的搭配分与分词代价 |
| INITIALS_LENGTH / MIXED_TYPED / COMPLETION | 简拼长度、混拼证据和补全代价 |
| PERSONAL_BASE / PERSONAL_FLOOR / PERSONAL_ADJUSTMENT | 新个人词基准、原词提升到基准的差值、正负反馈 |
| SPELLING | 选中拼写路径的实际代价 |
| CHARACTER_LM / CORRECTION_CALIBRATION | 最终字符模型分与纠错校准，只加入一次 |
| EXTERNAL_BIGRAM | 最终外部上下文搭配分；不把 beam 中的临时搜索分重复加入 |
| sourcePrior（独立列） | 最终 ranker 采用的来源先验 |

分项沿真实词边累积，保留每个候选的词边、原始权重、归一化分母、来源、Float 分数和
获胜路径索引。同一文本的多条来源路径保留，不用参考答案挑路径。

Double 分项和与 Float 按原顺序运算的差异单列为 `arithmeticError`，上限断言为 0.0002；
它不是训练特征，也不是缺失得分的兜底桶。本批实际最大差为 **0.0000051772**。

### 生命周期与开销约束

- 只在显式主机 observer 范围内建立身份表；每次 decode 的 `finally` 释放表。
- 未启用时不创建分项向量或词边记录，也没有逐键日志；用 observer 计数快路径避开
  生产进程的逐词 ThreadLocal 查询。计数支持并发、嵌套、取消与异常清理。
- `Candidate` 的字段、相等比较、缓存对象均不增加诊断元数据；内部 CompositionPath
  仅增加一个可为空的证据引用。
- 主机观测绕开已有 prefix candidate cache，得到完整实际路径，并且不写入缓存。
  普通解码仍走原缓存；温缓存和观测结果做全等检查。
- metadata 从其他候选继承时，保留胜出分数路径的证据，不误用 metadata 提供者的权重。
- 个人词格边已测试；M19 使用空个人词库，其导出不代表 Adaptive 外层全部个人调整。
- CHARACTER_LM 仍是一个包含既有裁剪、插入先验和 OOV 规则的加权分项；未宣称拆开了
  每次字符概率或记录所有被 beam 丢弃的路径。

## 对照结果与真正发现

复用 E11 已经打开过的 31 句开发回放，生成 270 个后缀 × 四种上下文 = **1,080 行**。
这是已知诊断数据，不是新的盲测或自然输入准确率。

1. 导出 **200,294 条候选路径**。Python 独立检查加性分项、Float 总分、词边文本、
   完整去重排序及获胜路径索引，全部一致。
2. 观测开/关的完整 progressive 结果一致；与 E11 修改前字节码保存的 **1,080 个
   完整结果 SHA-256** 也全部一致，包括 prefix 候选、得分与元数据，而不止首选文本。
3. 未优化 ThreadLocal 与最终快路径的所有导出行/分项也完全相同，只有来源哈希不同。
4. 参考答案在 1,060/1,080 个池中出现；其余 20 行是当前搜索/候选池的缺口，单靠该池
   重排不会召回缺失文本。四种模式与同一句各切点相关，不是 1,080 条独立样本。
5. editor 模式中，**17 个状态、来自 5 个来源句**，有一个非参考路径在全部 16 个加性
   分项和来源先验上支配所有参考文本路径。忽略 Float 舍入并使用严格正系数时，仅缩放
   这些分项仍会优先该路径。审计同时检查参考文本的全部保留路径，避免仅比较它的旧赢家。

例子：

- `我 + huabuhaowujiaoxing`：`花不好五角星` 对 `画不好五角星` 的分项差为
  词库权重 +0.1226、内部搭配 +0.1859、字符 LM +0.4428、外部搭配 +0.1294。
- `抱歉 + huifuwanle`：`恢复完了` 对 `回复晚了` 的词库权重差 +0.7447、字符 LM 差 +0.9248。

这说明“只要学几个正向系数就会解决整句语义”预期过强。下一步仍可测固定池重排的收益，
同时应比较 train-only 更丰富的词/长上下文证据。对代词和合理同音变体继续单列，
不把单一参考文本自动当成唯一合法表达，更不从这些例句制作生产加权表。

### Android 与开销记录

第一版 observer 未启用时仍做 ThreadLocal 查询。其 ABBA 64 次确认均符合固定预期文本；
基线/初版中位数 **230/238.5 ms**、观测 P95 **379/416 ms**、最大值 **511/428 ms**。
样本不足以把波动单独归因于这段代码，但没有理由为主机诊断保留逐词 ThreadLocal 查找，
因此增加了计数快路径并重新构建。

第一次追加功能测试中，warm 10 项完成后，我开始重建，导致后续 SkipInstall 的 APK 哈希
一致性检查终止了旧轮次。此项是测试调度错误，不是输入法故障；旧日志保留，最终版重新
安装后另用 `e12-final-*` 执行，未把中止轮次计入最终版验收。

最终版重新安装后：warm 10、上下文 8、混拼 3、纠错 8、学习/隐私 2，合计 **31 项通过**。
延迟对照后再次安装最终包，重复 2 项学习测试，最终包共 33 次功能测试执行。
实际 SQLite 读取确认程彻 useCount=4、智能体 useCount=3，近期强反馈分别约 2.58175、
1.74999；隐私输入的程澈不存在。重启后候选截图已查看，程彻位于首位。

最终快路径与同一 E10 基线重新进行 ABBA，**64 次确认均通过**。基线/最终版：
