# E14：运行成熟引擎对照，拆开词库与语言模型，而非直接换引擎

状态：完成主机参考适配器和四组数据消融；**保留 Sense 默认引擎**。
这批结果不支持直接替换为所测参考版本。新模型/词库改善了旧参考引擎，但还有明确首选
损失和重复运行的同分次序漂移。当前上游完整引擎、Android JNI 接入均未在本轮完成。

## 为什么这样比

E13 学习六个旧特征的独立收益很小。本轮转向词级语言证据与成熟实现，实际运行参考库，
同时避免把 README、旧发行版、新数据和新版引擎混成一个对象。

- 当前上游 libime 的 `LanguageModel` 用 KenLM `QuantArrayTrieModel`，沿词节点传播
  语言模型状态，不是 Sense 当前字符 trigram 的同名包装。
  [固定源码](https://github.com/fcitx/libime/blob/171edcf137001e8eb8274f53ec010058cda70b09/src/libime/core/languagemodel.cpp)
- `UserLanguageModel` 将静态词模型与用户历史概率组合，并保留静态得分下界；这是研究
  个人适应方式的参考，不代表 Sense 已经移植该规则。
  [固定源码](https://github.com/fcitx/libime/blob/171edcf137001e8eb8274f53ec010058cda70b09/src/libime/core/userlanguagemodel.cpp)
- 词格实现有帧裁剪、前向搜索、后向 N-best 和已有格的更新；它给“复用增量状态”提供
  具体对照，而非只增加一个缓存层。
  [固定源码](https://github.com/fcitx/libime/blob/171edcf137001e8eb8274f53ec010058cda70b09/src/libime/core/decoder.cpp)
- Fcitx5 Android 确实包含 libime/fcitx5-chinese-addons 的 Android 接线，但其整个键盘
  framework 不是此次移植目标。Sense 的 UI、InputConnection 和 Agent 保持自己的前端。
  [项目](https://github.com/fcitx5-android/fcitx5-android)

## 实际运行对象

本机已有 Ubuntu WSL。把发行版的 **libime 1.0.11-1build1** 和依赖下载、解包到专项
G 盘目录；没有 apt install，没有切换系统输入法，没有加载个人历史。
所有下载包按 apt 元数据 SHA-256 验证。当前上游固定为 `171edcf...`，其版本是 1.1.17；
**本轮执行的二进制不是 1.1.17**，新版纠错 API 也不在这次测试中。

新增 `libime_reference_probe.cpp`，使用公开 API：

1. 构造共享词库/模型，每个 query 新建 `PinyinContext`。
2. 设置 NBest 10、Inner，保留该版本的 beam 20 / frame 40；逐字符输入完整拼音。
3. 导出引擎原顺序、得分、消耗拼音长度和完整句子；没有 learn/save。
4. 成对指标只取完整覆盖输入的去重中文候选前十；另记原列表首项，八组实际回放两者
   均无首项差异。参考库和 Sense 的整体搜索预算不同，不称作等预算算法竞赛。

旧版包用的是旧词库/旧 LM。因此再固定下载当前上游指定的两个数据包：
[固定构建清单](https://github.com/fcitx/libime/blob/171edcf137001e8eb8274f53ec010058cda70b09/data/CMakeLists.txt)

| 对象 | 固定哈希 / 内容 |
|---|---|
| `lm_sc.arpa-20260629.tar.zst` | `06808333b9173e5374cf2cb5afc12d08f5625bf9abb536489cac376fc05f2e7f` |
| `dict-20260907.tar.zst` | `fb75a179065e690dfc4559ce1807cbaf4fbe4f0111a5005615be9f435e6b9d76` |
| 本机重新编译的 LM | 34,736,327 bytes；`3588b3942c8fd62e1a6bd3bae8c7cadc0faf928c175b245224ed475862218387` |

ARPA 头记录 270,714 个 unigram、4,789,953 个 bigram、2,189,434 个 trigram。
按上游参数 `-s -a 22 -q 4 trie`，用本地旧版 KenLM 工具转换；这是**新版数据在旧引擎上
的数据消融**，没有冒称完整上游构建。新模型的干净 model-only 配方重建出相同字节。

新字典含旧编码器不认识的大写字母等拼写。通用兼容过滤器调用旧 `PinyinEncoder` 验证：
300,624 条原始记录接受 300,526 条、排除 98 条；每条排除及异常原文均保留。
保持原始权重，不查询任何评测答案。记录数不是去重词条数；未使用扩展 B 字典。

旧发行包 copyright 和依赖许可已留存；两个新数据压缩包内只有数据文件。下载来源与
校验值可核对，新的训练语料谱系和随 APK 分发材料仍需专门整理；本轮仅本地主机使用，
没有把旧 Debian copyright 当作新训练数据已全面核验的证明。

## 数据、指标和边界

重用 E13 已打开的 64 句 dev 和 124 句 test，只测整句无外部上下文。两批现在都是
**已知诊断数据**；不重新称作盲测。上游模型的训练资料与 Tatoeba 的交集未确认，
也不据此声称自然输入总体准确率。Sense 对照是 E13 的原 baseline，不使用未部署的学习权重。

冻结参考程序、输入、旧库和新数据的配置后运行四组：旧/旧、新 LM/旧字典、旧 LM/新兼容字典、
新/新。所有分组都报告，不只选择最高分的一组。

新 LM 确实改善旧引擎；单独替换字典未带来首选总数增加。新/新组合的候选前十比 Sense
多召回两句，但首选明显较低，**更多候选覆盖不等于更好的默认上屏**。

新/新首次的五个首选改善包括“这里的通风很差呢”“我向妈妈学习”“我买不起这么贵的轿车”。
十四条损失包含“这个年轻人是医生→这个年轻人是一生”“已经是时候回去了→已经逝世后回去了”
和“你如果需要雨伞→你如果需要与三”；另有买/卖、的/地、他/她等单参考歧义。
每组的完整改善/损失、原始候选和所有逐句结果均在对应 comparison JSON 中。

### 重复运行暴露的不稳定次序

新/新 124 句重复，去掉计时后 **123 个完整候选列表相同、1 个不同**。
`womenmingtianqutiaozaoshichangba` 的“我们明天去跳蚤市场吧/把”同分 `-28.1390705`，
两次前两项次序对调，首选总数 82→81。原次序保留，没有在评测后偷偷追加参考答案优先
或字典序排序。`controls.json` 的 `passed=false` 明确保留了这一项。
这只是当前旧引擎/新量化模型组合的实测；没有将原因未经验证地推给现版 libime。

## 验证与工程问题

- 新比较器五项测试覆盖完整终止、配置、身份配对、前缀/去重、有限分数、相同前十截断。
- 全部 Python 375 项：374 通过、1 项 Windows symlink 能力相关跳过。
- 实际 C++ adapter 的参考答案变更不影响输出；两个 fresh context 相同输入结果相同。
- 兼容过滤器实际 fixture 覆盖 tab/space、可省略 score、两条不支持拼写，接受/排除各二条。
- 四配置共 752 次整句回放；重复 124 次及隔离控制 4 次，共 880 个 query 执行。
  它们不是 880 个独立句子，主要工作负载只有 188 个来源句。
- 三次接线问题保留了原始日志：旧头文件没有新纠错枚举；KenLM 的 unlink 后 resize
  在 DrvFS scratch 上失败，切到独立 RAM scratch；新字典同时使用空格/tab、可省略权重，
  且含旧编码器不支持的大写拼写。最终干净配方与过滤子集均单独验证。
- 本轮 Sense Kotlin 解码、词库资产、UI 与已有 APK 全部保持；没有新的 Android 构建、
  功能或延迟实测。E13 的 879 项主机结果是上一阶段证据，不重复计成本轮执行。

## 接入决策与下个切片

目前不直接移植这个旧二进制，亦不把新数据包立刻装进默认 APK。下步优先补齐**异域输入
评估**：长期只在同一 Tatoeba 来源上训练/测试，有明显域偏置；上述对照同样受此限制。
先使用来源和许可明确的另一个文本域，以及短词/姓名/技术词和不完整逐键状态，再选择
“更强词级模型接入现有词格”或“当前原生引擎后端”中的工程方向。

若做原生后端，保持以下边界，而非把整个第三方输入法 UI 移入 Sense：

1. 通过既有候选快照协议返回文本、消耗的原拼音范围、全词/前缀身份、版本号。
2. 一个会话的原生 context 只由一个候选 worker 使用；JNI 返回过时结果时丢弃，
   不在另一个线程释放仍在计算的原生句柄。模型共享与会话可变状态分开。
3. 编辑框/隐私模式切换清上下文，原始按键和候选文本不记入生产逐键日志。
4. Sense 的词条强正反馈、撤销选词、拼音分隔符、英文 Enter 和 T9/五笔仍走已有契约；
   新模型不覆盖用户明确确认，个人存储不作破坏性迁移。
5. 先有关闭开关和旧引擎回退，再做外部编辑框系统测试、损坏模型测试、真实 Android
   尾部延迟与内存对照。主机 C++ 的微秒字段只用于定位，不代替这项验收。

证据入口：`benchmarks/results/e14-evidence-manifest.json`、`e14-acceptance-gate.json`。
原生库和大语料留在独立 G 盘参考目录，以完整哈希锁定；未复制到项目 assets 或发布产物。

干净复现顺序：本地解包参考依赖 → 构建 probe → 冻结旧参考 → 旧参考回放 → 下载固定数据
→ 解包转换工具 → `build_libime_reference_model.sh` 生成新 LM → 兼容字典过滤/构建
→ 冻结数据消融 → 各组回放和比较 → 实际重复/答案隔离控制。所有结果路径使用新文件。
