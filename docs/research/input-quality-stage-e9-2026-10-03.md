# E9：扩充词库后的混合拼写召回保护

## 结论

本轮修复一个“词库越大反而找不到原有词”的搜索问题。没有调整具体词频、LM 权重、模型或字典资产。

补充词条产生了更多同前缀路径，原来的混合拼写扩展按顺序花完 96 分支/4096 探测预算后，
尚未到达基础词库中本来存在的词。目标词在进入语言模型评分之前已经丢失。

修复后，扩充视图只有在发生预算截断时，才补做一次拥有独立预算的基础视图搜索，再合并候选。
低置信补词继续可用，不通过禁用新词库来掩盖问题；普通未截断查询不触发第二遍。

### 对旧结论的更正

E7 曾据一次探针把 `yisscp → 艺术收藏品` 的缺口归为“基础词库加 LM 也存在”。这个归因证据不足。
本轮校验旧基础字典 SHA-256，并重新编译封存的 E7/E8 源码进行分层探测，得到：

| 字典与模式 | 动态混合候选池 | 最终结果 |
|---|---|---|
| 原基础字典，legacy | 有“艺术收藏品” | 有 |
| 原基础字典，LM 0.5 / OOV −4 | 有 | 有 |
| 扩充字典，legacy 基础视图 | 有 | 有 |
| 扩充字典，LM 扩充视图，修复前 | 空 | 空 |

因此此次属于扩充词库之后的召回回归，不是 LM 认为这个词不合理。旧报告和原始探针记录保持原样，
以本报告及新的隔离构建证据修正其解释。基线代码完整取自 E8 封存文件；生产核心仅 `PinyinDecoder.kt` 改变。

## 实现边界

- 为二分查找、候选读取增加明确的只读索引视图参数，默认仍使用当前视图。
- 动态扩展返回是否发生预算截断；扩充视图被截断后才启用基础视图补查。
- 每遍仍最多 4 个分词路径、每路径 4096 次前缀探测、96 个分支、16 个精确记录。
  最坏额外工作有界，合计最多两遍；保留协作取消检查。
- 不复制字典字节、不新建词典对象；两种视图共享 E7 已有不可变载荷。
- 基础补查不读 tier-2，随后与扩充视图结果去重、应用同一套语言评分。
- 非 LM/T9 路径不增加第二遍；非拥挤补充词仍通过回归。

## 固定重放

### 字典读音重建：192 个词，960 条

`mixed-recall-v1` 从已许可的 Frost 本地源文件按 SHA-256 顺序抽样；
3/4/5 字 × 原始权重低于 100/其余，共 6 组，每组 32 个读音。
每个读音生成完整全拼、首/中/尾保留全拼、交替保留全拼五种输入。
抽样不读取解码结果，字典源哈希和 GPL-3.0-only 来源见同目录 `notice.json`。

这是合成拼写的词典检索检查，不是自然用户意图或盲测准确率。缩写本身可能有多个合理答案。

| 指标 | 修复前扩充字典 | 修复后 |
|---|---:|---:|
| 960 条目标首选 | 597 | 611 |
| 目标前十 | 728 | 745 |
| 目标在 255 候选内 | 748 | 765 |
| 完整全拼 192 条目标首选 | 189 | 189 |
| 完整全拼 192 条召回 | 192 | 192 |

原基础字典召回 764 条。扩充后丢失的 17 条，在此样本中全部恢复；修复后没有新增目标首选丢失或召回丢失。
192 条完整全拼的完整结果指纹均保持。混合输入有 81 条完整结果变化，并保留 5 条非首选目标的名次退步：
“一串串”17→18、“张建伟”13→14、“赚不着”4→5、“埇桥区”25→27、“太犟了”29→30。
这不构成对所有词条、所有缩写的单调召回保证。

### 已有句子控制：2,819 条

沿用固定 dev/test 的句子及合成错误，不新增调参。LM 0.5、OOV −4、候选上限 255、无学习。

- 目标首选 1316、前十 1889、255 内召回 2085，前后相同。
- 所有首选文本、目标词名次均保持，没有目标名次退步。
- 9 条完整结果指纹变化，逐条保存在 `e9-ordinary-recall.json`，未伪称全结果相同。
- 这些重放按原 M15 行为移除 `joints` 撇号，显式分词仍由 E8 的系统场景单独覆盖。

## Android 与成本

同一测试 APK 对 E8 旧包运行 3 个真实按键场景，全部失败，外部编辑框残留原始拼写：
`yisscp`、`xqdluo`、`tcsfei`。新包对应得到“艺术收藏品”“心情低落”“停车收费”。

最终开发包的功能组包括混合拼写 3、显式分词 6、普通输入 10、纠错 8、联想 9、冷加载 4、学习/重启 2；
完成状态及各包哈希由 `e9-acceptance-gate.json` 校验。主机 855 项通过；Python 342 项运行，1 项 Windows 符号链接权限跳过。

同一专用 API 37 x86_64 模拟器的 ABBA 有 64 次成功确认（每包 32 次）：

| 固定工作负载 | E8 | E9 |
|---|---:|---:|
| 确认中位数 | 205 ms | 199 ms |
| 观察 P95 | 343 ms | 341 ms |
| 最大值 | 383 ms | 363 ms |

部分输入变慢：“请发个位置给我”174.5→183.5 ms，“这个应用很好用”165→176.5 ms，完整逐项结果均保留。
不把一次小样本 ABBA 当成全面提速证据。被恢复的 17 条混合拼写，在主机单次重放的解码中位数
1.58→2.86 ms，表明额外搜索确实有成本；这个数字不是 Android 输入延迟。

功能断言与像素截图有一帧时差，最初三项通过时截图仍可能是前一帧原始拼写。
渲染复查版本只增加等待界面空闲/下一帧，不改变断言或生产代码，单独保留 `e9-mixed-render` 证据。
