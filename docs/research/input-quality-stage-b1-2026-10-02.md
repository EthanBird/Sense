# Sense 输入质量 B1：句子语料、统计 LM 和端侧查询实现

## 本轮结论

已完成真实句子语料的可重建准备流程，训练并验证字级 1/2/3-gram 基线，
以及 Kotlin 的低分配模型加载和条件概率查询。**生产候选路径仍未启用这个模型。**

固定模型的冻结语料困惑度：unigram **358.95**、bigram **63.38**、trigram **50.97**。
模型 3,090,930 字节；Python/Kotlin 579 个混合 seen/backoff/OOV 打分对照全部通过。

这些数字证明语言建模与二进制实现有效，不等同于输入法首选率，也不宣称已经解决全部上下文歧义。

### 清洗、分组和隔离

1. NFKC，再用 OpenCC `t2s.json` 统一简体字形；不擅自作地区术语转换。
2. 只保留汉字、空白和标点，汉字总长 2–64；包含拉丁字母/数字等内容的行本轮不用于 LM。
3. 标点/空白切断字符链，不制造跨标点搭配；保留至少两字的连续汉字段。
4. 简繁和标点变体按汉字骨架去重；6–64 字、编辑距离至多 1 的骨架构成近重复连通族。
5. 按整个族的内容哈希分配 train/dev/test，桶比例 90/5/5，不随机拆同族句子。
6. 排除现有 replay 的精确骨架、近重复族和六字以上子串；同样排除这些长句的近邻。
7. 额外删除 dev/test 与早期分片完全重复的汉字段，避免标点分句后的隐性重复。
8. 每个保留记录关联逐句贡献者、原文、ID、链接、许可和转换说明，保存在 `attribution.jsonl`。

近重复规则不是语义改写检测；当前只对明确的字形、标点和单编辑变体提供隔离保证。
准备后共有 82,114 个族，最大族 22 个不同骨架。记录分布：

| 分片 | 记录 | 汉字段 | 汉字 |
|---|---:|---:|---:|
| train | 76,736 | 94,195 | 776,701 |
| dev | 4,066 | 4,792 | 40,529 |
| test | 4,089 | 4,876 | 41,076 |

技术类启发式标签在三个分片仅有 259 / 11 / 13 条记录。会话/普通/技术标签用于分层诊断，
不是人工标注的领域真值。这批例句对技术聊天覆盖薄弱，后续需独立补充领域评测。

## 模型定义

使用绝对折扣插值，**不是 Kneser-Ney**，也不是从原词库搭配特征换个名称。

```text
P1(w) = (count(w) + 0.1) / (total + 0.1 * vocabulary)
Pn(w | h) = direct(h,w) + lambda(h) * P(n-1)(w | suffix(h))
direct(h,w) = (count(h,w) - 0.75) / count(h)    # retained entries
lambda(h) = 1 - sum_w direct(h,w)
```

低于剪枝阈值的 direct 项为零，被移除的质量进入 backoff，保持概率归一。
字频阈值 2、bigram 阈值 1、trigram 阈值 2；每段两个 BOS、末尾一个 EOS。
稀有/未见字符映射到 UNK，这个统一类别的概率不代表每个未见汉字各自拥有同等总质量。
后续解码融合需要处理 OOV 与用户人名，避免 UNK 概率异常鼓励或过度压低罕见字。

这些参数在首次冻结测量前固定，未根据 test 调参。准备脚本加固近邻排除、训练器加固署名检查后，
重建所得三分片哈希与模型字节均保持一致。

### 开发 / 冻结测试

困惑度按“汉字 + EOS”token 计算，各模型使用同一词表和数据。值越低越好。

| 模型阶数 | dev | test |
|---|---:|---:|
| 1-gram | 364.51 | 358.95 |
| 2-gram | 64.99 | 63.38 |
| 3-gram | 52.54 | 50.97 |

测试是独立命令：验证冻结模型哈希、corpus manifest、test 文件哈希及跨分片的族/汉字段隔离。
拟合命令只解析 train/dev。集成测试把 test 文件替换成无效内容后，训练仍产生同一模型；
删掉署名 sidecar 则训练失败。开发和测试 JSON 均保留各领域的交叉熵、困惑度和 OOV 数。

## Kotlin 端侧组件

- 新接口 `CharacterLanguageModel` 接受前两个码点、下一个码点，提供条件 log P 与 unigram log P。
- 新加载器 `BinaryCharacterLanguageModel` 使用 5 组排序原始数组；不为每次查询创建字符串/Map。
- SCNG/1 保留 3,352 个词表 token、127,109 个 bigram、89,418 个 trigram。
- 观测项保存完整插值概率；只有缺失项才应用 backoff，避免重复插值。
- 文件大小限额 16 MiB；分配前核对头、计数和总长；再检查严格排序、Unicode/特殊 token、有限分数及上下文引用。
- 普通 core 测试包含 698 字节自编语料 fixture；没有把第三方句子塞入单元测试资源。

M10 对实际 3.1 MB 模型测得：加载约 51 ms，估算常驻数组 payload 3,090,904 字节；
10,000 次主机条件转移查询 p50 400 ns、p95 800 ns、p99 900 ns。包括计时开销，不是 Android 帧时间。
Python/Kotlin 最大绝对 log-score 误差约 `1.91e-6`。

## 输入候选的探索证据

`tools/probe_lm_nbest.py` 仅对保存的 M8 前三候选做探索重排，完整记录所有固定权重和退步。
它使用排名先验 `-ln(rank)` 与平均字 log P 或 PMI 特征，**不是当前生产打分，也不是完整词格搜索**。

- 原首选 28/40，前三候选 oracle 34/40。
- 平均字 log P 权重 0.5：31/40，3 个改善、0 个退步。
- 权重 2.0：32/40，4 个改善、0 个退步。
- 权重 4.0：31/40，4 个改善、1 个退步；“输入法还需要优化”退为“输入法还需要有话”。
- 高 PMI 权重也把“回复”推为“恢复”；没有隐藏这些损失。

M8 已是开发诊断集。这组实验提供接入方向，不是独立 P2C 泛化结论，更不证明仅重排前三个就足够。
