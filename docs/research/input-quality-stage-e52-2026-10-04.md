# E52：延后词边元数据创建，分配改善但尾延迟未过

## 决定

**保留原输入实现。** 候选版本通过完整输出等价和功能回归，但固定 ABBA 的 P95 增加，
未通过事前“中位数与 P95 均不退步”的联合门槛。没有重跑挑选结果，也没有调整门槛。
实验代码、产物身份和全部结果保留；本轮仅提交回放身份校验工具及研究记录，不发布新 APK。

## 实验针对什么

现有纠错 scout/full-beam 共用词边选择缓存。然而 `composePaths` 在检查缓存之前，
总会把整批候选转换成 `CompositionOption`，重新求首码点、末码点和码点个数。
命中缓存时，结果已携带这份不可变元数据，新创建的一批对象随即丢弃。

唯一产品实验是：用一个词边局部 holder 延后构造，直到选取路径真正需要元数据；
普通无 LM 分支继续使用同一列表。没有新增跨查询缓存，没有改分数、候选数、模型或 beam。

事前列出三种解释：缓存命中时的冗余创建确实有成本；主要延迟也可能来自其他搜索步骤；
新的局部 holder 本身会增加一些开销。用完整回放、分配计数和系统输入分别区分，
不把“少分配对象”直接当作“手机输入更快”。

同一已知的 3,083 个逐键状态，真实 `AdaptivePinyinDecoder.decodeProgressively`，
空个人词库、LM 权重 0.5、OOV −4、上限 255，资产保持：

| 项目 | 原实现 | 延后创建 |
|---|---:|---:|
| 完整候选结果及 LM 调用差异 | — | 0 |
| 解码线程累计分配计数估计 | 37,826,995,184 B | 36,285,839,160 B |
| 相对变化 | — | −4.074% |

166 个状态分配量增加，最大单状态增加 6,112 B，其余逐条数据保留。
该计数来自 Java 17 ThreadMXBean，包含 JIT/逃逸分析影响，不是 Android 常驻内存或精确对象数。
421 core、317 service、235 UI 共 973 项单元测试新执行通过，Debug/fixture 构建成功。

### 一次回放命令身份错误及修复

第一次候选回放在修改命令数组时改错下标，classpath 仍指向基线 JAR。
命令身份核对发现后，该次结果被明确排除；更正 classpath 后使用新输出文件运行候选。
不是因为结果不好而重跑。原错误命令、输出及排除理由全部保留。

新增 `verify_replay_classpath.py`：检查显式 classpath 中到底哪个 JAR/目录提供
`PinyinDecoder.class`，要求唯一提供者为预期产物并核对摘要，而非仅检查候选路径“出现过”。
9 项回归覆盖错误主类下标、另一 JAR 抢先/重复提供类、helper 目录遮蔽、摘要不符及隐式路径，
以及校验失败时阻止进程启动、校验后启动、已有日志保护。`--run-log` 将校验接到实际启动前，
而非要求调用者记得手动检查。工具对两份有效命令通过，对错误命令按预期报错；
另有 10 项既有延迟报告工具测试通过。启动顺序单测使用 subprocess mock，不算额外 Java 回放。

## Android 结果

专用 `emulator-5580` / `sense-input-quality`、API37、应用堆属性 192m；没有操作实体手机。
候选 APK 摘要 `a52ff4ec36d91dc765e18e85cb2d227491ce94906e01de9b0dbd2be1d7a0e39e`。

49 项普通输入、学习/重启、上下文、纠错、分词和联想检查通过。
上述主机与功能任务结束后，执行唯一一轮原实现→候选→候选→原实现，64 次确认及 8 次立即续打正确。
四块实测发键间隔中位数均 34ms，P95 为 36/36/36/37ms，均通过注入节奏门槛。

| 确认上屏延迟 | 原实现 | 候选 |
|---|---:|---:|
| 中位数 | 146.5ms | 135ms |
| 观测 P95 | 328ms | 346ms |
| 最大值 | 349ms | 371ms |

| 输入 | 原实现中位数 | 候选中位数 |
|---|---:|---:|
| 你好 | 98ms | 83.5ms |
| 我喜欢北京 | 218ms | 226ms |
| 请发个位置给我 | 127ms | 123ms |
| 请检查一下邮件 | 152ms | 148.5ms |
| 这个应用很好用 | 121ms | 125.5ms |
| 今天有一点类（既有错误输出） | 128.5ms | 128.5ms |
| 汤姆和玛丽每天晚上都看电视 | 200ms | 201.5ms |
| 汤姆没有注意到玛丽换了新发型 | 222.5ms | 213.5ms |

五个输入的观测 P95 增加。小样本不证明普遍退化或统计显著性，但没有满足本轮已冻结门槛，
因此不接纳。这里的确认延迟含注入和调度、排除首轮词库加载，不是渲染帧时间或自然真机分布。
