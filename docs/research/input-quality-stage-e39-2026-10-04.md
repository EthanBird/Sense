# E39：一次前向的轻量候选评分器——成本通过，质量失败

## 结论

已实现并实际训练 **MiniRBT encoder + 原评分残差头**，每个候选一次前向，而非逐字遮盖。
桌面 CPU 新增重排中位数约 8 ms、P95 约 11～13 ms，但日常语料首选和字错率退步。
**固定试验到此停止，不接入 Android、不覆盖 rc.4，不继续扫描训练轮数或权重。**

这次交付的是可运行的训练/评估工具、保护契约及失败证据，不是输入法已经启用的新模型。
现有可下载版本仍为 [v0.4.16-rc.4](https://github.com/EthanBird/Sense/releases/tag/v0.4.16-rc.4)。

## 固定方案与真实输入特征

政策 `benchmarks/corpus/e39-student-policy.json` 在新候选导出前冻结：

- 使用 `hfl/minirbt-h256@446e1b4012b10946f479563005700c54c9db3f7c` 的 encoder，
  丢弃此前未通过任务资格的 MLM 头与 pooler；新建零初始化标量任务头。
- 输入 `[CLS] + 最多两个汉字上文 + 候选 + [SEP]`。
  CLS 拼接当前解码器导出的 **16 项实际命名分数特征 + source prior**，数值除 32、裁剪至 [-4,4]。
- 输出 `原始总分 + 8*tanh(新头输出/8)`，候选同分保持原先顺序。
  不把参考答案、正确排名、教师分数作为在线推理特征；原始答案只用于训练监督及事后评价。
- 仅重排前八项中等长、2～24 字的纯汉字槽位。
  一旦涉及个人词、纠错或其他未训练来源，整行保持原顺序；未知字、特征缺失及异常分数同样回退。
  不改变候选集合，不删除低分项，不在推理时调用教师。

M19 在**当前生产解码器**上导出实际路径，并确认观测前后完整 progressive result 相等。
训练 1,024 状态共 128,391 条路径；两域开发 256 状态共 34,250 条路径。
独立核对真实词频边、特征求和、来源优先项、赢家去重和零增量顺序；
开发集完整结果摘要与 E36 原生产基线逐行相同，未复用 E13 已过期特征。

## 训练与工具修复

固定 seed 39，AdamW；encoder 学习率 1e-4、新头 1e-3、weight decay .01、梯度裁剪 1，
每步四组、固定四轮，只评估最后一轮。损失为 `.75 * gold CE + .25 * T² * teacher KL`，T=2。
751 组每轮 188 步，训练损失依次为 **1.5772、1.4397、1.2516、1.1202**。
101 个 encoder 张量确实发生变化，不是只给冻结模型套未训练输出头。
751 组训练输入及 256 个开发状态的零头/零增量均精确恢复原有排序。

训练开始前修复三处工具兼容问题，完整早期源码与中断记录保留：

1. Kotlin Float 最短文本在 Python 被读成 float64，比较零增量时应先还原实际 float32 总分。
2. M19 的 id/cut/mode 与 M20 的 id/cut 键对齐；mode 由采样 cut 确定且仍作独立校验。
3. 旧权重存储了 `embeddings.position_ids`，当前 Transformers 将其作为非持久 buffer 重建。
   只在该 buffer **精确等于 arange(max_position_embeddings)** 时忽略；学习参数依旧 strict load。

前两处发现后中止了教师准备，而非正在训练的模型。最终复用第一轮已经完成的 381 组纯 PLL 分数，
逐条核对相同输入、模型及评分数学代码，并实算前八组确认逐值一致；不复用旧浮点特征。
剩余分数正常计算，最终输出 751 个完整监督组。重用计时含快速读取，不用于推理加速结论。
没有在查看学生开发准确率后修改模型、阈值、轮数或数据。

保护范围内教师仍明显好于学生，说明这次蒸馏没有保住已有语言证据。
有限弱监督量、残差结构或训练目标可能是原因；本轮没有做区分它们的消融，避免将猜测当结论。
这个事后对照不用于修改门槛或选择其他 checkpoint。
