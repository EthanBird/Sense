# F1：上下文词级联想与异步输入法接线

日期：2026-10-02。26 键全拼优先；局部开发阶段，不是 release 发布或真机认证。

## 结论

此前联想的静态分支只看最后一个字，常在“你好”后显示“的／了／好”等低信息量单字。
本轮引入离线 **1～3 字上下文 → 后续词／词内剩余部分** 模型，并学习语段结束 STOP。
低置信度时维持工具栏，不为填满一行硬凑候选；个人历史仍参与排序，也可覆盖静态 STOP。

已接入真正的 `InputMethodService`：推断在独立串行线程执行，结果绑定编辑会话和上下文。
“今天 → 早上”可整词插入外部编辑框；“你好”在没有个人续写历史时不弹出低质量单字。
这两个示例是模型行为测试，不是生产词条白名单。

## 一、研究与比较

[Moon IME（ACL 2018）](https://aclanthology.org/P18-4024/) 将输入转换与联想结合，提示联想需要
独立于简单码表匹配的上下文证据。本轮借鉴任务划分，不声称复现其神经/检索架构。

比较三类模型：

1. 原有词库字二元搭配分数；
2. 已训练的字符三元 LM，枚举有直接证据的后继字和高频 unigram 候选；
3. 新的词／后缀联想模型，使用相同 train 语料，独立计数和 STOP 门控。

单纯改用字符 LM 提高续字召回，但本对照在所有语段末尾仍提供候选，且全是单字。
本轮选择更克制的词级模型，不将“处处有候选”当作联想成功。

## 二、训练、选参与证据边界

- 复用固定 Tatoeba 普通话数据、作者署名和来源族分片。train 76,736 条、776,701 汉字。
- 字词单位由现有 SPLX 规范词条和频率做 Viterbi 分词；最大 8 字，未知单字保留。
  这不是人工金标准，也不是 HMM/CRF 或神经 LM。
- 在每个字之后产生下个词或当前词剩余后缀；1～3 字上下文、折扣 0.75、平滑 0.1。
  固定裁剪：上下文至少 3 次、普通直接边至少 2 次、最多 32 条直接后继、最终最多 8 候选。
- 比较 9 个配置。选取无长度奖励、首项概率至少 0.02 且大于 STOP 概率的配置。
  选择规则是在查看开发集及示例后制定的，不称预注册；规则与参数在本任务测试前冻结。
- 之后固定模型运行一次测试。未将测试答案加入词库或训练计数；未按测试结果调参。
  语料分片此前用于字符 LM 研究，这也不是新收集的自然输入盲测。

完整开发回放 40,529 个截断位置，导出模型与 Python 预测完全一致；
其中 28,703 个唯一上下文还通过 Kotlin `LocalAssociationEngine` 的完整候选顺序对照。
开发、测试的完整观测和原始哈希保存在 `benchmarks/results/f1-raw/`，不是只报挑选示例。

## 三、固定测试结果

4,089 条源记录，4,876 个片段，41,076 个观测位置；其中有后续文本的 36,200 个。

| 指标 | 原二元单字 | 字符 LM 对照 | 新词级 STOP 模型 |
|---|---:|---:|---:|
| 精确后续单元 Top-1 | 4,213（11.64%） | 7,653（21.14%） | 7,258（20.05%） |
| 精确后续单元 Top-3 | 7,364（20.34%） | 10,623（29.35%） | 9,998（27.62%） |
| 后续文本前缀 Top-3 | 10,491（28.98%） | 15,762（43.54%） | 11,781（32.54%） |
| 后续文本前缀 Top-8 | 14,959（41.32%） | 20,047（55.38%） | 13,914（38.44%） |
| Top-3 含匹配的多字续写 | 0 | 0 | 1,721（4.75%） |
| 词边界处精确 Top-3，分母 13,986 | 342（2.45%） | 1,069（7.64%） | 643（4.60%） |
| 语段末尾仍提供提示，分母 4,876 | 4,818（98.81%） | 4,876（100%） | 683（14.01%） |

**取舍和不足**：新模型比旧模型有更多整词命中、更少结束后提示；但前八项单字续接覆盖下降，
也没有在所有召回指标上超过字符 LM。真正词边界的精确命中率仍低，应与包含词内后缀的整体指标分开看。
词级训练量小、词单位偏差、末尾三个字的上下文限制仍会产生不自然尾项，例如“今天”后的“气”。

“语段末尾出提示”是打扰倾向的代理，不是实测用户打扰率；多字命中不是已节省击键数。
每处只有一个观测续写，未命中也不自动表示建议不合语法。个人历史未混入该静态质量对照。

## 四、Android 接线与生命周期

- `BinaryContextAssociationModel` 用字节表、`LongArray` 键和 `IntArray` 偏移；只解码命中的一行。
- SNWP/1 大小 3,756,683 字节，73,253 个上下文，其中 44,483 行有候选。
  APK 内压缩为 2,521,317 字节；模型加两组原始索引约 4.64 MB，不是实测进程增量堆占用。
- 固定长度与 SHA-256；严格校验 UTF-8、Han 标量、键顺序、候选重复、有限分数、字数和表大小。
  空行阻止继续使用更短上下文；缺失／损坏的文件才退回旧二元模型。
- 用户词继续按频率／近期程度排序。静态分数为 `3 + logP`，使新观察可领先，陈旧一次性观察不永久垄断。
  这是与既有历史分数的兼容映射，不声称经过用户偏好概率校准。
- `AssociationQueryController` 至多一个运行和一个待处理任务；重复渲染复用同一查询／显示快照。
- 工作线程只接收已捕获字符串，不访问 `InputConnection`；回投再次检查显示票据、会话 ID、
  连接对象身份、原上下文、模型实例与隐私状态。取消或销毁后，已排入主线程的旧回调也失效。
- 420 ms 静置显示、4.5 s 闲置收起保持；计时从实际展示开始。D7 的按住／拖动暂停收起保留。
  新模型不修改正在 composing 时的拼音词格，也不修改 26 键布局。

## 五、性能实测与修正

API 37 x86_64 专用模拟器，库级 instrumentation，12 个固定上下文，两模型各 2,000 次交错查询，
500 轮热身；查询阶段禁用个人历史。它与真实系统 IME 测试分开，不代表手机端总体按键延迟。

| 查询耗时 | 原二元模型 | 新模型 |
|---|---:|---:|
| 中位数 | 0.0827 ms | 0.0272 ms |
| 观测 P95 | 0.2026 ms | 0.0356 ms |
| 最大值 | 0.5656 ms | 0.4208 ms |

首次装载的初版逐词分配 String/解码器/集合，单次观测 1,455 ms；改成完整字节校验后观测 673 ms，
最后包含常见已分配 Han 区间快路径的版本为 811 ms。三次均为单次新进程观测，不称统计显著改进；
最后版本没有在装载时间上胜过上一观测，完整记录保留。查表计时不含这部分成本。
装载仍在输入引擎的后台初始化链上，额外就绪成本需要继续关注，应与热查询微秒数分开报告。

## 七、下一步

1. 继续研究日常对话中的真实词边界质量，不通过降低 STOP 阈值重新制造工具栏干扰。
2. 扩大 UI 的横屏、大字体和不同系统验证；为辅助功能用户评估闲置超时。
3. 回到词句排序／纠错先验校准；E3 已记录的模糊音和同音歧义不足仍未解决。
4. 如拆分联想模型异步初始化，需覆盖首次加载时“模型晚到、原请求已取消”的回调边界。

本阶段没有宣称达到主流输入法整体质量；最高优先级的输入质量目标继续进行。
