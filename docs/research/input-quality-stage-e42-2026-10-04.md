# E42：组词码表前缀区间查找

## 变更依据与范围

E41 的真实触摸线程采样把组词路径和码表字符比较列为热点。
本轮先检查“不同 beam 路径重复整理同一词边”的猜测：现有代码已把这部分放在路径循环之外，
因此没有再增加一个功能重叠的缓存。

实际改动针对 `composePaths` 的另一个重复工作：每个可到达起点向后延长一个字母时，
旧实现对该子串重新搜索整张码表。新实现利用字节码表本身的字典序：

1. 当前区间内的记录已共享前 n 个字母。
2. 仅比较第 n+1 个字节，二分收窄到下一前缀区间。
3. 区间首项若长度恰好等于该前缀，就是原查找应返回的 exact 记录；否则保持无 exact。
4. 一旦区间为空，后续更长前缀也无匹配，剩余结果保持 -1。

基础／扩展视图分别使用自身 offset 数组，返回各自的本地记录编号。
不复制字典为 trie，不改变资产格式，不扩大常驻索引，不保留跨查询缓存。
每个可到达起点最多临时保存 25 个 Int（100 字节数组负载，对象头另计）；基础词边仍最多 24 个拼音字母。
个人长词的旧通路继续独立执行，不因基础词边长度上限被截断。

词边验证、强制分词边界、个人覆盖、语言模型、词频、beam、候选预算及排序均保持。
新增查找在每个前缀边界检查协作取消，取消时不发布部分结果；没有改服务层 latest-only 或提交队列。
这是**单次组词中的前缀区间复用**，不是已经实现了跨按键增量 beam。

## 记录身份与完整结果

新增 5 项单元测试覆盖：短词与扩展词、未命中后不重新扩大区间、非零起点、别名码、
稀疏 offset 视图、无符号长码长度、固定随机词典、空区间与非法边界、取消及并发只读。
这是等价优化，没有宣称旧版存在错误选字；本轮未制造一个“旧实现选错词”的 red 测试。

`PrefixLookupAudit.java` 从实际加载的字典对象读取 immutable bytes 和两套视图，
按固定每 43 条记录采样，覆盖原码、带偏移码和错误延长码；所有长度前缀都与原 `findExact` 对照。

## 实际快打决定：接纳

同一 API37 x86_64 专用模拟器，E34 原 Debug / 本轮 Debug / 本轮 Debug / E34 原 Debug。
每块 8 查询正序、倒序，共 64 次确认、8 次立即续打；全部功能、逐字前缀及实际发送节奏检查通过。
沿用运行前固定的中位数和 P95 双指标不回退门槛，只运行一次，不选择有利重跑。

### 交付边界

本轮接纳的生产代码是 `PinyinDecoder` 的词边 exact 记录来源及新增纯函数；没有重新启用 E41 字符 memo。
完整证据见 `e42-acceptance-gate.json` 和 `e42-evidence-manifest.json`。模拟器恢复 Gboard，
无 debugger 等待或遗留 adb forward。阶段提交时线上 rc.4 保持不变，发布构建另记版本和证书证据。

下一重点仍包括跨按键增量路径复用、自然同音句与模糊音排序、以及更广设备/UI 生命周期；
本轮没有改变准确率，也没有完成全部专业化目标。
