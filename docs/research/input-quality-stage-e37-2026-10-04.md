# E37：神经候选重排与模型准入失败诊断

## 结论

本轮交付离线字符 PLL 重排工具、可重放数据和模型准入检查，**没有修改安卓默认排序或发布包**。
选中的 `hfl/rbt3` 固定权重不适合作为即用的零样本 MLM 评分器：开发重排大幅退步，
随后在上游项目找到公开版本缺少配套 MLM 任务权重的明确说明。
因此，这轮首先是**模型资格判定失败**，而非证明神经语言模型路线无效。

应先读完整上游说明、验证任务头再开展质量评测。只检查模型卡 `fill-mask` 标签、
张量名称存在和严格加载成功，仍不足以证明预训练任务可用。这个遗漏已转为显式阻断条件。
不继续给这个 checkpoint 调候选数、混合系数或阈值；rc.4 保持原样。

## 来源、固定条件与实现

- 方法参考 [Masked Language Model Scoring](https://aclanthology.org/2020.acl-main.240/)：
  逐个遮住候选字符，累加其条件自然对数概率；不是读取未遮住目标时的自复制 logits。
- 模型 [HFL RBT3](https://huggingface.co/hfl/rbt3) 的模型卡标注 Apache-2.0。
  固定 revision `0aa0527ff4170f29e1dfd3eb6ef60dc67e1bf75c`，
  权重 SHA-256 `3e04f7477f55dffce2a2fbc4d0ba35068415162a9e92e3d5cc74a49781ba4eb0`。
  下载文件 156,380,647 bytes，实际 38,499,464 参数 / 153,997,856 参数字节。
- 没有选用 UER L2/H128：其当时的模型卡/API未明确标注权重许可，未以工具仓库代码许可替代权重许可。
- `e37-neural-rescoring-policy.json` 在准确率输出前固定，完全不训练、不扫描参数。
- 复用 E36 **原生产**候选输出；逐个核对当前 core main 源文件、词库、LM 和输入摘要后才开始。
  两个域各 128 个状态（整句 / 已知正确上文的中点后缀），均是已打开开发回归，不是新盲测。
- 仅重排前 8 项中与原首选等长的纯汉字槽位，长度 2～24；其他位置保持。
  任一参与字符未登录则整行跳过；所有 255 项候选成员保持。正确答案只进入事后统计，不传入评分 API。
  已知上文最多 2 字，仅作条件，不计分。尚未处理生产个人词强选择、纠错来源优先级等，因此只是可行性基线。
- 本机已有 CPU PyTorch 2.6.0 / Transformers 4.48.3，无新增依赖安装。
  权重只用 `weights_only=True` 读取，不导入远端代码；推理离线，模型和缓存放 E 盘，未进入 APK 或 Git。

优化只在独立遮字的 hidden states 上计算 MLM 输出头，避免完整 `batch × length × vocabulary` logits。
随机微型 BERT 测试与真实 RBT3 检查均验证等价；真实模型最大 logit 差 **0**。
每字仍独立遮盖，不将多个目标一次全部遮住偷换 PLL。

## 先发现并修正的词表解析错误

首个启动在 tokenizer 一致性断言处停止，尚未运行质量数据。
原因是 Python `splitlines()` 会把词表中的 Unicode 行分隔字符当作换行，导致后续 token ID 偏移。
改用官方 `BertTokenizer.get_vocab()` 作为唯一映射，并新增含该字符的回归。
保留首次失败日志及原始锁文件；修正后真实 tokenizer、逐字符 IDs、完整/优化输出头及重复计算均一致。
这属于评分工具修复，不是针对观察到的开发结果调参。

## 实际结果：保留失败，不推广错误模型

| 已知开发域 | 状态 | 首选 | 前五 | 255 项召回 | 首选字错 |
|---|---:|---:|---:|---:|---:|
| AISHELL | 128 | 65→34 | 97→85 | 118→118 | 142→181 /1087 |
| 日常 Tatoeba | 128 | 83→43 | 113→102 | 121→121 | 70→134 /941 |

AISHELL 10 个首选改善、41 个损失；日常 8 个改善、48 个损失。
每个损失、完整候选和 PLL 分数留档，没有仅摘选改善例句。分别 7 / 6 个状态因未登录字符跳过。
六个既有“类/累”诊断仍为 4/6，出现一进一退，不进入采用门槛。
总计 249 次实际重排、15,548 个独立遮字输入。

预热后、CPU 两线程、mask microbatch 32，**额外重排**中位数 / P95：

- AISHELL：192.89 / 531.69 ms；
- 日常：131.72 / 422.87 ms。

这些不含原解码、Android UI 和模型加载，不是手机延迟，也不是完整输入耗时。
模型构造及装载约 562 ms；含库导入、文件摘要检查的构造约 4.45 s，均单次记录。
质量门槛失败，不做 Android 移植或量化以掩盖质量问题。

## 为什么先判 checkpoint 不合格

失效后执行基本填空诊断，例如“北京是[MASK]国的首都。”的最高输出是“前”，
“中国的首都是[MASK]京。”最高输出是 `10000`。这些诊断只用于归因，不用于新一轮挑模型成绩。

进一步做了两个控制：

1. 官方 `BertForMaskedLM.from_pretrained` 直接本地加载同一权重，与本工具逐 logit **完全相等**；
   无缺失/形状不匹配参数，仅共同忽略 NSP 与 pooler 张量。故已排除本工具的加载变换或输出头优化造成差异。
2. 上游 [Chinese-BERT-wwm 固定 README 第117行](https://github.com/ymcui/Chinese-BERT-wwm/blob/4c256d460f30cf899f42a16f4125be205e9ea270/README.md#L117)
   明确说明其公开版本未包含 MLM 任务权重，MLM 使用需要额外预训练。
   权重文件存在非零的 MLM 形状张量，不代表它们与当前 encoder 构成正确训练的任务头。

`e37-model-qualification.json` 记录这个证据。后续默认启动先检查资格，在加载权重前停止；
只有 `--reproduce-rejected-checkpoint` 显式诊断开关才允许复现实验，仍不代表准入生产。
