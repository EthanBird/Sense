# E48：延后路径首字母串拼接，减少分配并保留完整候选

## 本轮决定

**接纳等价的执行成本优化。** 生产分数、词库、模型、搜索空间和排序规则保持。
3,083 个完整 progressive 结果及 LM 调用逐行相同；主机解码线程累计分配量减少 **6.38%**。
固定专用模拟器 ABBA 的确认中位数 **146→146 ms**，观测 P95 **315→292 ms**，最大 **339→311 ms**。
64 次确认、8 次续打均正确，达到事前双指标不退步门槛；3 个查询中位数仍变慢，详见下表。
这些是固定工作负载证据，不作普遍低于 100 ms、整体准确率增加或所有手机提速的声明。

## 从采样到实现

E47 减少 bigram 调用却没有设备收益，因此本轮不再增加缓存。
先对 E46 固定 JAR 的已知 3,083 状态执行 JFR 主机分配采样：17,977 个事件、约 43.95 GB 加权采样量。
`LanguageOption` 约占 5.8%，不是最大项；路径、字符串及数组占比更高。
采样量是估计值，不是瞬时内存、精确对象数或 Android 分配统计。

代码中每次路径扩展都创建 `path.initials + edge.initials`，即使路径随后被截断。
完整内容只在导出 Candidate 时使用，另一路纠错过滤只检查其长度。
本轮唯一改动：

- 每个路径保存已存在的父路径引用和当前词边首字母字符串。
- 以一个 Int 保存相同的累计长度，保持纠错音节数筛选，不为此提前生成字符串。
- 仅在导出候选时，迭代父链并按偏移填入字符数组，生成正序首字母串；没有递归或跨查询缓存。
- 汉字文本、所有浮点运算、边选择、去重身份、裁剪时机、beam 和候选预算原样保留。

父引用可能增加临时保留，导出时也有代价。因此没有仅凭代码观感接纳，而是同时验证完整输出、
解码分配量和实际 Android 输入。当前证据不等价于“保留堆大小下降 6.38%”。

实现编译时补齐纠错长度的使用点和显式 Int 类型，修正前日志亦保留；冻结测量后没有再更改生产实现。
