# E17：旧边界 bigram 的定向消融与完整恢复

## 结论

**仅移除旧边界分也不是正确的默认修复。两个预注册试验都未过双域开发门槛，运行时代码已恢复到 E16。**
它能解释、缓解个别错误切分，但会伤害原本正确的“谈判组被解散”“好是蔡依林”等表达。
不继续用这两组已打开的数据调小常数；下一方向是更充分的词/长上下文证据，并扩大短词与逐键路径验证。

## 固定假设与实现范围

E16 观测到 `散步 + 怎么样` 相对 `三 + 不怎么样` 只以约 .11068 分领先；后者有 .25178 的旧边界 bigram 优势。
因此在候选运行前固定 `e17-boundary-policy.json`，只试两种模式：

1. 原日常模型，LM 生效时令内部边界 bigram 权重为 0。
2. 固定 E16 最小非零融合权重 .1，并同样令内部边界权重为 0。

保留外部编辑器上下文 bigram、词频、拼写先验、LM +6/截断/权重、候选预算。
无 LM 及个人新词的 LM backoff 路径保持原边界证据。
默认值仍为 1，默认路径直接返回原 Float，避免给对照引入额外乘法误差。
主机 M22 输出显式记录融合权重和内部边界权重；93 项输入在运行前锁定。

## 开发结果

| 模式 | AISHELL 首选 / 前五 / 字错 | 日常首选 / 前五 / 字错 |
| --- | --- | --- |
| 当前基线 | 65 / 97 / 142 | 83 / 113 / 70 |
| 日常模型、去内部边界 | 61 / 97 / 144 | 82 / 113 / 71 |
| .1 融合、去内部边界 | 76 / 103 / 104 | 83 / 113 / 71 |

每域 64 句、128 状态（整句和正确上文中点后缀），字错分母分别为 1,087 / 941。
预先要求每个领域首选、前五、召回非降，字错非增，同时两域合计首选严格增加。
第二种在新域改善，但日常多 1 字错，仍未过关。`selectedMode=null`，两个已冻结的测试分片继续未执行。

具体退步均保留原始前五、目标名次和完整候选：

- “随后员工谈判组被解散”→“随后员工谈判祖辈解散”；对应中点后缀也退步。
- 上文“象刚”后的“好是蔡依林女粉丝”→“好事蔡依林女粉丝”。
- 原模型去边界后，上文“冲第”的“三棒的时候呢”→“三磅的时候呢”。
- 两种试验都把上文“么否”的“决了你的建议呢”变成“绝了你的建议呢”。
- 融合去边界仍保留“近露天过夜吗”→“近路天国也吗”的退步。

因此 E16 提出的“旧边界证据存在重复/偏置”是一个局部机制，**不足以支持全局删除它**。
它同时承担了当前有限 LM 没覆盖好的证据。下一步需要更强的词边与长上下文模型，不以给这几个句子写特判来过评测。

## 验证与回退

- 新 5 项定向单元：真实得分追踪中的 INTERNAL_BIGRAM 归零、默认和无 LM 等价、外部上下文保留、个人新词 backoff 保留、非法配置拦截。
- 试验版本完整 core **345 项通过**；这不表示候选质量通过。
- 主回放 768 状态；两域默认对 E16 的完整 progressive SHA 相同，共 256 状态。
- 失败后把两份改动运行时文件、M22 入口和试验单元共 4 份源码保存到 `e17/trial-source/`。
  `PinyinDecoder.kt`、`PinyinLanguageScorer.kt` 按已归档 E13 字节及 E16 哈希精确恢复；M22 和试验单元移出生产构建。
  没有对原用户工作区执行 git reset、clean 或覆盖操作。
- 恢复后先命中 Gradle 缓存，另以 `--rerun-tasks` 实际重跑 core **340 项通过**，两份日志分别保存。
- 恢复后另跑两域 256 状态，完整 progressive SHA 与恢复前默认/原 E16 基线一致；过期 M22 字节码已移除。
- Python **391 项**，390 通过、1 项 Windows 符号链接权限检查跳过。
- 本轮没有 Android UI/性能测量，没有新 APK、commit 或 release。默认模型、资产、既有 APK 保持。
