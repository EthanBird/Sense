# E19：按实际拼音覆盖区分输入和补全

## 已落实的修复

本轮不换词库或语言模型，修复默认 26 键全拼的一项真实输入缺陷：
`nix` 按空格，旧包写入“你想要的是什么”，修复后写入“你想”。
不是只修未启用的四元实验模型。原三元模型同样给未输入的句子尾部发放了逐字奖励。

当前实现保留：

- 完整拼音、完整简拼、混合拼音的已有 LM 评分与个性化规则。
- 正在输入的最后一个音节的证据，例如 `beij` 已涉及“北京”两个字，而不是只涉及“北”。
- 合法未完成首音节的原始拼写，例如 `go/gon` 仍候选 `gong/gou`，不抢先改写为 `wo/gen`。
- Enter 原始英文、回删、外部编辑框、个人词重建、九宫格/五笔的旧路径。

远端 HEAD/main 本轮重新核对仍为 `d457eecdfe938f0473fd1a6d4b0d3d43166356f0`，
与独立工作区基点一致；原工作区改动保持。

## 复现与定位

实际路径追踪，不从最后排名反推分数：

| `nix` 候选 | 来源 | 原 LM 项 | 原最终分 |
|---|---|---:|---:|
| 你想要的是什么 | literal prefix | 14.078 | 15.183 |
| 你想 | mixed full/initial | 2.990 | 13.040 |

原完整路径特征每字使用 `(logP + 6)`，用于词格内比较不同词边；
同一奖励又被用于整条预测补全。对于短查询，可预测的长尾不断增加正分，
即使用户没有输入对应音节。`wox` 在原三元下已把长句放到第二位，四元会进一步抢到首位。

先写回归再修改：首轮 5 个测试有 4 个失败，覆盖真实生产资产、统计前缀、
带完整拼音的前缀，以及得分归属。旧 Android APK 的四个共同用例有两个失败，
两个失败都实际上屏了“你想要的是什么”；正常 `wox` 与 Enter 原文通过。

## 为什么没有采用最简单的降权

第一版直接取消所有 prefix 字符的插入奖励。它修复 `nix`，却让 `f/p/q` 出现
“啊”等不相关纠错，并削弱 `zhine` 的正常未完成音节。这版被拦下，源码、日志和 APK 保留。

第二版只取消**未输入尾部**的奖励，恢复单字母和未完成音节；扩大检查又发现
`go/gon` 的候选可能被编辑距离生成的“我/跟”取代，于是增加合法未完成首音节的纠错边界。
最终规则不是“短输入一律放短字”或给几条例句加分，也没有扫描新权重。

## 最终实现

### 音节覆盖 DP

`PinyinSyllableSegmenter.coveredPrefixCharacters` 使用当前字典的音节集合和候选的逐字声母：

1. 连续消耗完整音节。
2. 允许最后一段是音节的未完成前缀；这一字算已涉及。
3. 不把零个字母算成下一个字；不引入纠错、简拼 beam 或最长词猜测。
4. 遍历与声母对齐的合法分段，保留最大已涉及字数。例如 `xian / xa` 覆盖“西安”两字，
   `xian / x` 覆盖一字；`xi / xa` 只覆盖第一字。
5. 查询长度仍受 96 字母上限约束，循环内有协作取消检查；同查询同声母串复用覆盖结果。

仅字典支持的 literal `BASE_PREFIX` 路径使用此调整。完整匹配与用户明确学习的词不改分域。

### LM 分数

保留原完整 LM 缓存和 Float 运算；从未输入、模型已知的汉字尾部扣除其已有的 `6 × weight` 插入奖励，
条件概率、查询归一化、OOV 独立特征仍保留。所有输出字均已涉及时，直接返回旧 feature，逐位不变。
补充平面汉字按 code point 计数；调整不写回共享 LM 缓存，不增加全局状态或学习数据。

### 未完成首音节

在启用 LM、有实际 literal prefix 候选、没有完整精确/组词路径，而且整个输入仍是某个音节的
真前缀时，先不运行编辑距离纠错。完成、非法、多音节输入仍走原纠错流程；`nihoa → 你好` 保留。
没有 LM 的旧路径保持，九宫格未被切换到新模型。

### 真实系统延迟对照

同一专用模拟器、固定八组输入、每组每版四次，按 A→B→B→A 安装对照包和最终包。
64 次空格确认结果均正确，四段应用 atrace 完整，没有未闭合 decode 切片。

| 指标：空格到外部编辑框 | 对照包 | 最终包 |
|---|---:|---:|
| 中位数 | 315 ms | 306.5 ms |
| 本次观测 P95 | 735 ms | 581 ms |
| 最大值 | 797 ms | 635 ms |

不据此宣称全面提速。单输入中位数仍有三项变慢：
`woxihuanbeijing` 362→375 ms，`zhegeyingyonghenhaoyong` 234.5→260.5 ms，
`jintianyouyidianlei` 265.5→271 ms；全部原始样本与 trace 留存。
两组长句分别为 468.5→421 ms、424→400.5 ms。
这包含注入、系统调度与轮询，不含初次资产装载，也不是自然输入的帧时间或实体手机分位数。
对照为 E12 留存 APK，期间 E13～E18 有未启用的实验类；因此是实际 APK 对照，不声称仅隔离 E19 一项因果效应。
固定 workload 的已有“类 / 累”语义错误按原先预期保留，本实验不算新的准确率评测。
