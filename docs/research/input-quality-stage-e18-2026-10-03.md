# E18：保留低阶模型的四元上下文扩展

## 决定

**离线开发和独立测试门槛通过，但暂不切换默认输入法模型。**

新增 SCQ4/1 稀疏四元模型、训练工具和词格状态接线；模型只在显式绑定时使用，
正式工厂仍加载原来的 SCNG/1 三元模型。不是把小幅离线提升直接发布给用户。
这轮真正拦住默认接入的是短码体验和运行成本：

- `wox` 的首选从“我想”变为“我想和你在一起”，主机和 Android ART 都复现。
- 独立新闻测试首选只净增 2 个状态；日常测试首选没有增加。
- 额外模型 2.97 MB；固定长句的 ART 解码中位数 234.0→275.8 ms。

下一阶段优先处理**已输入拼音的覆盖、未输入部分的补全、整句 LM 分数之间的边界**，
以及 limit=12 与前端实际 255 预算下的排序一致性。不是继续扫描模型权重或扩大模型。

## 预注册与实现

政策：`benchmarks/corpus/e18-fourgram-policy.json`，训练前固定：

1. 原 SCNG/1 的词表、1/2/3-gram 条件概率逐字节保持。
2. 仅三个前字均为已知汉字时，启用 train 中出现的四元证据；BOS/UNK/EOS 不作扩展上下文。
3. 绝对折扣 0.75、最低四元计数 2；剪枝质量交还原三元回退，不丢失概率质量。
4. 无保留上下文时直接返回原三元值。没有外部上下文时，前三个输出字符的概率不变。
5. 两个预先确定的训练方案：仅原 Tatoeba train；原 train + E15 已冻结的等字符预算 AISHELL train。
6. LM 权重 0.5、OOV 特征 −4、纠错校准 12、候选上限 255 不变；旧内部 bigram 保留。

条件形式为 `P4(w|abc) = max(count(abcw)-0.75,0)/count(abc) + λ(abc)P3(w|bc)`。
实现是绝对折扣插值，并非 Kneser–Ney、HMM、CRF 或神经网络。

SCQ4 头绑定原模型 SHA-256。三字上下文使用 63-bit key，后继字符单独保存；
加载校验版本、长度、上限、排序、引用、有限对数概率和回退表。
查询使用原生数组二分。词内/跨词传递第三字状态；查询内缓存包含完整状态；
标点重置，补充平面字符按 code point 处理。个人新词回退及零权重路径保留。

外部编辑框仍只采集原来的最近两个完整字符；第三字主要随候选路径累积。
没有扩大编辑器读取范围，也没有修改隐私或会话生命周期。

高阶 n-gram 的背景参考 [Chen/Goodman](https://aclanthology.org/P96-1041/)
与 [Goodman 技术报告](https://www.microsoft.com/en-us/research/publication/a-bit-of-progress-in-language-modeling-extended-version/)。
这里是受移动端预算约束的独立实现，不声称复现论文结果。

## 独立测试

AISHELL v7 test 与日常 v8 test 各 124 句、248 状态；两域两模型共 **992 次解码**。
标签在查看候选前由 agent 复核，不是独立人工标注。中点上下文来自正确答案，
同一句的两状态相关；两种来源也不是自然手机输入。

| 测试域 | 首选 | 前五 | 前十 | 255 内召回 | 字符错误 |
|---|---:|---:|---:|---:|---:|
| 新闻 | 150→152 | 194→196 | 204→204 | 223→227 | 226→222 / 2,033 |
| 日常 | 170→170 | 213→213 | 223→222 | 236→236 | 129→127 / 1,833 |

新闻 3 个首选改善、1 个损失，实际来自 2 个改善来源句和 1 个损失来源句。
“贷款首府比例”→“贷款首付比例”改善；“三是科技支撑将更加有力”退为“三十科技支撑将更加有力”。
新闻 short 分层字错 129→130；日常前十少 1 条，全部名次退步留在逐条报告。

按来源句聚类的 10,000 次配对 bootstrap，仅作事后描述：
新闻首选差 +0.81 个百分点，95% 百分位区间 **−0.81 到 +2.82 个百分点**。
区间跨零，不据此宣称普遍质量提升。日常首选完全未变，零宽区间也不代表总体等价保证。

评测工具在读取训练报告字段时发现 baseline hash 实际位于 policy，正式汇总前修正了字段读取。
首用脚本快照、旧/新脚本 SHA 与理由均保留；模型、输出、选择和验收规则没有变化。

## 逐键、短码与记忆保护

真实 AdaptivePinyinDecoder 上执行 367 个已知诊断输入 × 空/两字上下文 × 12/255 限额：

- **1,468 个配对状态**，每模型再解码一次，**2,936 个完整结果重复一致**。
- 跨模型完整结果相同 1,101 个；不同不自动等于改善或错误。
- 其中 1–3 字母状态 1,188 个；996 个完整结果相同，1,186 个首选文本相同。
- 两个首选变化均为 `wox`、limit=255：短词“我想”被长补全“我想和你在一起”压过。
  这说明“前三个输出字符概率不变”不等于“短输入排序不变”，长补全仍获得额外上下文奖励。
- 两模型的“程彻/智能体”显式学习、再次默认接受、存储重建后首选保护共 **12 个断言通过**。
  这里的重建是内存词库快照，不冒充新的 SQLite/进程重启/隐私设备测试；D4/E12 已有证据另存。
- 控制程序英语加载上限写为 80,000，而当前资产恰为 20,000 条，实际加载词集与默认 20,000 上限一致。

真实模型数值控制：3,352 个发射符号、70 个条件分布，最大概率质量误差
`7.748916e-8`；234,640 个旧两字 API 值按 Float bit 完全一致，10,056 个 BOS 第三字条件值一致。
这是数值正确性，不是候选质量证明。

## Android ART 成本

仅专用 API 37 x86_64 模拟器的 library instrumentation，1 项测试通过。
使用相同词库、不同绑定模型，预热后八条固定输入 ABBA 次序；每输入每模型 8 次，
共 **128 次测量**，完整 progressive 结果与各自参考值一致。
这是进程内调用，未经过键盘 View、系统 InputConnection 或触摸，非手机帧延迟。

| 指标 | 原三元 | 四元扩展 |
|---|---:|---:|
| 64 次混合样本中位数 | 35.65 ms | 36.99 ms |
| nearest-rank P95 | 241.16 ms | 276.77 ms |
| 最大值 | 254.75 ms | 370.90 ms |
| 长句单项中位数 | 234.04 ms | 275.80 ms |
| 估算常驻数组字节 | 3,090,904 | 6,072,092 |

八个输入中七个的单项中位数增加；`wox` 抢首选也在 ART 复现。
解析加载的首轮受 JIT/类加载影响大：原模型 1,233 ms，扩展 380 ms，不比较为冷启动提升。
后续三轮原模型 55.7–62.8 ms，扩展 174.1–178.4 ms，均不含文件读取。
数组估算不含对象、临时字节和进程 PSS；模型成本尚不适合默认推广。
