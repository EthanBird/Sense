# E34：跨音节换位纠错的搜索成本

## 目标

接回 E31 已证实的跨音节换位召回，不扩大搜索预算或针对个别词加分。
例如 `wobuxihuaznuoye` 中的相邻交换跨越两个音节，应只计一次既有 0.45 换位成本。
E31 的候选实现因 Android 耗时门槛失败而未发布；本轮不是把旧失败重新标成通过。

生产候选由三部分组成：

1. E31 保留两个音节终点的组合边，显式撇号边界继续生效。
2. 有界复用普通音节边的计算，不缓存汉字候选、个人词结果、语言模型状态或最终组句。
3. 最终版本将图的路径/边链式比较器换成等价的原始类型比较，减少排序时的装箱和调用层次。

评分、词库、模型、48 条生产拼音路径预算、完整组句预算都保持原值。

## 诊断与修改依据

先在专用 API 37 x86_64 模拟器运行冻结 E30 / E31 APK：
暖场 `nihao` 后，对首次和重复的 `woxihuanbeijing` 真正键盘触摸进行 ART 采样。
候选译码发生在真实 `:ime` 的 `sense-candidate-decoder`，测试末尾恢复原 APK 摘要及输入法。

三个假设分别是图状态/排序工作、下游语言模型及组句工作、首次编译/回收影响。
观测到普通边枚举和图排序是具体热点；跨音节边枚举本身未成为主导。
采样会改变编译、取消及实际完成的前缀数量，两个根区间 CPU 总量不当作版本性能对照。

加缓存的 V1 仍未通过正常触摸门槛。追加该产物的同样采样：首次输入时图剪枝
inclusive 134,185 μs，其中 PATH_ORDER 链 inclusive 73,419 μs；
`PathState.getCost` exclusive 43,552 μs。重叠 inclusive 数值不相加。
V2 据此只再替换 PATH_ORDER / EDGE_ORDER 比较实现，不改变排序键或搜索名额。

## 局部边复用的正确边界

每个 `PinyinSpellingGraph` 对应一个不可变音节库存，其独立缓存最多 128 项、4,096 条边；
超大结果不保留，空结果仍占条目配额，LRU 淘汰，完整不可变快照发布。
并发缺失在锁外计算，命中和发布使用短锁，保留协作取消检查。

普通音节边只依赖：

- 后续最多“库存最长音节长度＋一个多键”的拼音片段；生产库存与兼容的 24 字母长单元均受界限约束；
- 片段内部显式分隔位置；
- 前一个原始拼音字母，用于已有多键 `h/g` 的模糊成本。

缓存保存相对位置的普通边，按原库存/消费长度顺序；复用后恢复绝对 end/editOffset，
再进入原来的绝对 key HashMap 去重、加组合边和排序。这样连完整排序键并列时的原稳定次序也保留。
没有把模型上下文、左侧汉字或用户词身份混进一个不完整的缓存 key。

初版局部 key 漏掉前一拼音字母，旧结果快照在 `wozenmegengangmujieshi` 真正失败；
补齐 key 和一个字母的回看后通过。失败日志及修复前源码均保存，没有更新 oracle 来迎合新输出。

## 等价性与输入质量

`SpellingGraphSnapshot.java` 使用独立类加载器和冻结 E31 JAR，在缓存实现前生成 1,481 条完整路径摘要。
其中 945 条来自既有开发回放，其余覆盖逐键前缀、删除、显式分隔、歧义库存、长单元、96 字母及不同预算。
CI 正反向运行，共 2,962 次完整路径一致；缓存另有不可变、容量、前字母/分隔隔离、取消及并发测试。

V1 / V2 均重放既有 945 条开发和 1,874 条测试记录，与 E31 每项非耗时观察完全一致，
包括目标名次、图路径、选择的组句探针、候选数、字符错误和带分数的前五候选。
另有 Tatoeba / AISHELL 各 128 个全句/中点上下文状态的完整候选结果摘要一致，首选仍为 83/128、65/128。
数据均为曾使用的来源重构与合成误触，不称新盲测或自然手机准确率。

因此保留 E31 的已知质量变化，而不是宣称缓存本身增加召回：

- 换位开发子集首选 85→123/189、前十 111→164/189；
- 换位测试子集首选 164→228/375、前十 235→328/375；
- 既有跨音节开发样本的 48 路径图对齐召回 3→61/61；
- 两条既有漏键样本仍从第 3 名掉出前十，未用词句特判掩盖：
  `taiwanhiwozuiaideguojia`、`tangmuxiangzhidaonalinegmaidaojianghuang`。

## 正常 Android 输入成本

每个改动过的产物只运行一组预先冻结 ABBA：原版/候选/候选/原版，
基线是已接纳 E33；八个固定输入正反序，每版 32 次确认，另有立即续打。
只清除专用模拟器 Debug 数据；32 ms 目标触摸节奏，正常运行不启用 profiler。
所有 Gradle、主机回放和整套工具测试结束后才测量。
门槛仍为中位数/P95 均不高于同轮基线，四块功能/实际节奏完整。

V1 全部 64 次确认、8 次立即续打通过，但确认中位数 135→137 ms、P95 317→319 ms，
严格门槛未通过，原始失败对照保留。差异不作统计显著性推断；不据此定位单个函数的回退。
V2 在独立的新四块中测量，使用同一门槛，不与 V1 混合挑选样本。

V2 四块 64 次确认、8 次立即续打全部通过；实际发送间隔中位数均为 33 ms，
各块 P95 为 35 / 36 / 35 / 35 ms。预先冻结的门槛通过：

| 同轮产物 | 样本 | 确认中位数 | 观测 P95 | 最大值 |
|---|---:|---:|---:|---:|
| E33 基线 | 32 | 138 ms | 307 ms | 312 ms |
| E34 V2 | 32 | 129.5 ms | 296 ms | 346 ms |

完整保留个别退步：`qingjianchayixiayoujian` 中位数 161→171.5 ms；
`woxihuanbeijing` 最大值 312→346 ms；汤姆/玛丽/电视长句最大值 202→204 ms。
不宣称每个输入都变快、最大值改善或所有场景低于 100 ms。门槛只使用事前规定的总体中位数和 P95。
最终 Debug APK SHA-256：`1dfa19d48e9fcfdb491f9bed56c24911192caebe3ce8e7f42c65d1b67895a9df`。

最终数值、逐输入观察和接纳判定见 `benchmarks/results/e34-acceptance-gate.json`。
这些是触摸到外部 EditText 回调的固定负载观测，不是绘制帧耗时或真实手机认证。
`jintianyouyidianlei → 今天有一点类` 的既有语义错误仍明确保留，不把延迟测例当成准确率证明。

## 验证与交付边界

V1 和 V2 分别完成 955 项主机测试：403 核心、317 服务、235 UI；不累加为一个测试总数。
工具套件执行 448 项，447 通过、1 项既有 Windows 符号链接权限测试跳过。
最终 V2 APK 新执行 34 项 Android 外部编辑框场景全部通过：纠错 10、普通输入 10、
个人词学习 6、上下文 8。纠错组包含两条跨音节换位端到端回归。
人工查看两张实际测试截图，外部编辑框分别为“我不喜欢作业”和“我不介意在雨中漫步”，
确认后组合态结束、键盘和工具栏正常可见；这只覆盖这些终态，不代表所有屏幕密度和交互过程。
测试结束已恢复 Gboard，系统 debug_app 为 null，无遗留 adb forward。
新增代码没有修改 UI 布局或用户词库格式，E33 优化保留；线上 rc.3 原包不覆盖。

原始失败、来源固定、ART 诊断、全量回放和 Android 事件由 `e34-evidence-manifest.json` 引用。
最初旧 APK 降级被系统安装保护阻止，没有进入测量；专用 Debug AVD 明确使用 `-d` 后恢复原产物成功。
第一次 oracle 启动的本地 stdlib 路径错误也保留，修正运行路径后才生成预期结果。

本轮不代表整个质量目标完成：自然同音句、逐键最新任务成本、更广设备与 UI 生命周期继续推进。
