# Sense v0.4.3 发布说明

## 版本

- Tag：`v0.4.3`
- 版本：`versionCode 18`，`versionName 0.4.3`
- 基线：`v0.4.2`
- 方向：发布 Agent Memory X-02 的 fail-closed 工程底座；不提前宣称跨 Session
  Memory 已可用

## Agent Memory X-02 安全底座

- 新增纯 Kotlin/JVM `memory-protocol` 模块，冻结 Feature Stage、Gate、Capability、
  execution class 与 fail-closed process view 的 closed domain；
- 新增纯 Kotlin/JVM `event-journal` scaffold，只报告
  `SCHEMA_ONLY_NO_STORAGE`，没有 append、read、recall、payload 或 path API；
- exact 45-entry Gate registry 继续全部为 `BLOCKED`，effective stage 固定为
  `SCHEMA_ONLY`；
- main、IME 与 Brain 仅有 process-local safe holder；不存在跨进程 watcher、snapshot、
  generation、A/B slot 或持久化 store；
- test-only ByteArray channel 只存在于测试源码，不进入 production JAR。

本版本的 X-02 是未来 Memory 技术的安全边界，不是 Memory 功能开关。它不创建数据库、
文件、目录、Key、Journal、Blob、索引或后台任务，不捕获输入框与 Provider 正文，不执行
Recall、Tool 或 Skill effect，也不授权 `DARK`、`SHADOW`、`CANARY` 或 `DEFAULT`。

## 零运行时影响证明

- `app`、`:ime` 与 `:brain` 的 production dependency graph 不依赖
  `memory-protocol` 或 `event-journal`；
- GitHub Actions 在独立 runner、独立 checkout 与独立 `GRADLE_USER_HOME` 中构建
  X-02 JAR 和发布候选 APK；
- 隔离构建不执行 repository tests，也不消费普通测试 job 的工作目录或 APK；
- 发布前逐 entry 检查 JAR/APK，拒绝 X-02 Memory path、测试类、非标准 DEX、JVM
  class、nested/prefixed ZIP/JAR 与非连续或无界 multidex；
- Release 只消费通过上述检查的 `sense-v0.4.3-clean-apks` artifact。

因此 v0.4.3 的用户可见 AI 状态机、流式反馈、工具箱、语音与输入体验继承 v0.4.2；
除版本标识外，不新增 Memory runtime 行为。

## 发布门禁

GitHub Actions 创建 Release 前必须通过：

- Release planner 的 versionName/versionCode 同步变化、versionCode 单调递增、tag
  missing/同 SHA 幂等与异 SHA fail-closed 检查；
- Gate 0 派生报告：99 fields、45 Gate 全 `BLOCKED`、100 个 acyclic work package；
- X-02 source、dependency、workflow、offline gate 与 artifact 对抗检查；
- protocol、brain-api、brain、runtime、service、UI、memory、journal 与 core 单元测试；
- M0–M6 Host 正确性与性能基准；
- Android Lint、Debug、Benchmark 与 Macrobenchmark APK 编译；
- `versionCode 18`、`versionName 0.4.3`、`minSdk 29`、`targetSdk 36`；
- 签名、zipalign、Manifest 组件、权限白名单、Soul、许可文件、词典/Bigram/英文资产哈希；
- Release tag 在上传前后均精确解析到本次 main commit；
- 发布后的 APK 与 `SHA256SUMS.txt` 必须重新下载并通过哈希复核。

## 已知边界

- 当前 Release 仍使用 GitHub 构建环境生成的 debug/benchmark signer，不构成 ADR 0015
  定义的 production release identity；旧 APK 签名不同可能需要卸载后安装；
- X-02 不包含 production Snapshot wire、MemoryBroker、Room/FTS、Keystore root、
  authenticated receipt、capture、recall、export 或 erasure runtime；
- API 29–30 的 persistent Memory stage 仍固定为 `SCHEMA_ONLY`；更高版本也必须取得
  后续设备与安全 Gate 证据后才能提升；
- 自动化不能替代 HyperOS、Pixel、Samsung、OPPO/vivo 的真机输入体验验收。
