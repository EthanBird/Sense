## 本轮目标：修复主键盘点击后的主题混色与频闪

`v0.4.5.beta.2` 完成 Renderer 拆分后，`KeyboardChromeRenderer` 开始独占自己的
`Paint`。主背景与底部系统栏仍复用了这一个可变对象，系统栏绘制结束时留下浅色
`0x18`、深色 `0x2A` 的 alpha。下一次按键触发局部
`postInvalidateOnAnimation(...)` 时，背景 shader 被该 alpha 调制，脏区会透出宿主
窗口底色，表现为点击后背景变色、深浅主题拼块和频闪。

本版本完成以下修复：

- 主背景与底部系统栏改用生命周期独立的 `Paint`，不再共享 shader、颜色或 alpha；
- 调色板切换时一次性重建背景 shader 和系统栏颜色，绘制热路径不增加临时对象；
- 保留按键矩形脏区与 VSYNC 合帧，不以每次按键全量重绘掩盖问题；
- Light/Dark 色对、键帽布局、候选栏、手势、Aurora 独立渲染和 IME 输入协议保持不变。

## 回归验证

新增 `KeyboardChromeRendererDeviceTest`，直接覆盖发生故障的 Canvas/Renderer seam：

- 同一 Renderer 连续向两个全透明 Bitmap 绘制，浅色和深色背景两帧 alpha 均必须为
  `255`，颜色必须完全一致；
- 在与主题相反的宿主底色上只重绘一个局部 clip，脏区像素必须与完整帧一致，clip
  外像素不得变化；
- 修复前该用例稳定失败，深色第二帧实测 alpha 为 `42`；修复后全部通过。

实体设备复验使用 Android 16 / API 36、1080×2400 的 Xiaomi 15 Ultra：

- 深色主背景在按键前、按键后 180ms 与 1.2s 均为 `RGB(21,22,23)`；
- 浅色主背景在相同序列中均为 `RGB(238,243,249)`；
- 连续点击录屏仅更新目标按键按下态和输入/候选内容，主键区未再出现主题切换。

正式发布仍由 `tools/local_release.ps1 -Publish` 在同一 release HEAD 上重新执行完整本地
Python、JVM/Android unit test、Lint、AndroidTest APK assembly、debug/benchmark
构建、M0–M6 benchmark、X-02 source/artifact gate、release APK 元数据与签名验证，
随后上传并从 GitHub Release 下载资产复核。
