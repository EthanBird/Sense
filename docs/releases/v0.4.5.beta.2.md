# Sense v0.4.5.beta.2 预发布说明

## 版本

- Tag：`v0.4.5.beta.2`
- Android：`versionCode 23`，`versionName 0.4.5.beta.2`
- 发布资产：`Sense-v0.4.5.beta.2.apk`
- 平台：Android 10+，`minSdk 29`，`targetSdk 36`
- 发布性质：GitHub Pre-release

## 本轮目标：架构拆分，行为与性能等价

本轮继续收窄两个大型 Android 入口的职责，目标是在保持产品行为、持久化协议和热路径
性能等价的前提下，为后续 Agent 工具、记忆和设置能力扩展提供可测试边界：

- `SenseKeyboardView` 保持单 Canvas 自定义 View 和既有公开入口，布局、绘制、交互、
  帧调度通过独立 controller/renderer/state holder 协作；不会引入逐键 View 层级；
- `SenseKeyboardSurface` 与独立 Aurora child layer 的边界保持不变，长时间动画不带动
  整张键盘重绘；
- 设置 Activity 收敛为生命周期、导航、权限和界面装配层；各 section 使用独立
  controller/repository/view-binding 边界，Tools 状态采用不可变快照，持久化与
  Keystore 工作从普通主线程交互移出；
- Provider/Speech 的 load/save/clear/validate 使用独立 operation generation，跨操作
  回调不再互相吞掉；About 的 NOTICE/License 首次读取也进入后台 I/O lane；
- Skills 草稿、revision/catalog generation、原子恢复快照和有界 durability handoff
  保持现有语义；普通设置页停止时不再等待 Skills fsync，已完成的历史列表在单 revision
  瞬时读取失败后仍可切换和重试；
- Agent、Memory X-02、IME 普通输入和 Provider 协议不因结构调整改变 wire/storage 格式。

## 性能等价契约

发布候选必须继续满足以下契约：

- 键盘总高度保持竖屏 `358dp`、横屏 `258dp`，顶部候选/工具栏共享 `45dp` 固定槽，
  系统底栏保持 `52dp`；
- 按键、候选命中、绘制和上屏热路径不等待词典搜索、文件锁、磁盘、Keystore 或网络；
- 不同 pointer ID 相隔 2ms 的输入保持独立顺序，DOWN 时冻结目标，退格 repeat 在所有
  退出与销毁路径停止；
- 候选拖动只更新 viewport，不触发按键 scene rebuild 或键盘 remeasure；最多 510 项
  display snapshot 仍可通过全局 `sourceIndex` 精确命中；
- 候选拖动、面板滚动和按键矩形脏区继续使用 VSYNC 合帧的
  `postInvalidateOnAnimation(...)`，不会退化为每个 MOVE 样本投递普通刷新；
- active Aurora 继续使用独立渲染层，parent redraw、callback 所有权、停止后残留帧和
  allocation 使用既有 Android device gate 验证；
- M0–M6 host benchmark 阈值保持原值。host 数值只用于同 runner 回归比较，真机帧时间
  与交互证据继续单独记录；
- Settings destination/startup 的毫秒阈值在固定设备采集同提交基线后冻结；本次不以
  未采集的数值替代基线。

## 本地发布门禁

`tools/local_release.ps1` 是本版本的权威构建与发布入口。正式 `-Publish` 流程强制：

1. 使用完整本地 Python、JVM/Android unit test、Lint、AndroidTest APK assembly、
   debug/benchmark build、M0–M6 benchmark 和 X-02 source/artifact gate；
2. 从固定签名配置重新构建 release APK；
3. 校验唯一 signer、固定证书 SHA-256、APK v3 signature、16K zip alignment、包名、
   versionCode/versionName、SDK 与 Manifest 权限；
4. 要求工作树无待处理文件，并要求 `origin/main` 精确指向本地 release `HEAD`；
5. 以 `v0.4.5.beta.2` 创建或复用同目标 tag 的 GitHub prerelease，上传 APK 与
   `SHA256SUMS.txt`；
6. 从 GitHub Release 二次下载两项资产，复核本地/远端 SHA-256、checksum 文件和完整
   APK 签名与元数据。

`-Publish` 与 `-SkipTests`/`-SkipBuild` 互斥。最终 APK 内容 SHA-256 由正式构建生成，
并写入随 release 上传的 `SHA256SUMS.txt`。

## 代码整合收口

X-02 production source、build authority 与 offline gate 的 exact SHA-256 已在源码冻结后
重新计算并人工审查；对应 boundary baseline 已同步刷新。正式 `-Publish` 流程会在同一
release `HEAD` 上再次运行 `python tools/test_check_x02_boundaries.py`、
`python tools/check_x02_boundaries.py` 与 artifact gate，并归档完整本地门禁日志、
benchmark 原始结果、APK SHA-256 与 signer 输出。

固定实体设备 Aurora/Settings 绝对性能证据按设备信息、刷新率、thermal 状态和 exact
target/test APK SHA-256 单独归档。
