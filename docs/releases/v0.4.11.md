# Sense v0.4.11 — 候选记忆与本地智能联想

- 发布日期：2026-08-18
- Tag：`v0.4.11`
- Android：`versionCode 36`，`versionName 0.4.11`
- 发布资产：`Sense-v0.4.11.apk`、`SHA256SUMS.txt`
- 最低系统：Android 10 / API 29

## 候选记忆修复

- 修复已学习多字词在生产候选上限下与深层基础组合候选碰撞后掉出前排的问题；强证据词条现在拥有稳定的总分下限，候选数量变化不会改变其学习效果。
- 修复输入“程彻”等多字词后只删除末字，却把整个词条当作拒绝并降权的问题。单次退格只会否定一个完整的单码点词条；整词选择删除仍会产生负反馈。
- 分段选词后确认整词时使用新的 `COMPOSED_CONFIRM` 证据，不再把明确组合完成的短语按弱默认上屏处理。
- 异步加载正式词库期间的可靠选择进入有界启动队列，词库发布后按原证据重放，不再丢失刚启动输入法时录入的词条。
- 相邻可靠上屏只建立上下文联想，不把任意连续句片误写成精确用户词条；精确词条仍来自用户实际确认的候选与分段整词。
- 为固定 Frost 词库尚未覆盖的现代高频词增加精确词汇覆盖，QWERTY 与 T9 输入 `zhinengti` 时“智能体”稳定出现在候选前两位，并继续接受用户排序学习。

## 智能联想

- 联想改为可靠上屏后的停顿触发：等待 420ms 后才短暂接管工具栏；连续输入会直接取消待显示任务，因此正常连打过程中没有闪现或布局跳动。
- 联想条与工具栏互斥，不再叠加绘制；右侧固定 × 可立即收起，闲置 4.5 秒也会自动恢复工具栏。开始组合、移动光标、切换输入框、打开其他面板或隐藏输入法都会终止当前生命周期。
- 点击下一词建议会写入当前外部输入框，并重新进入“停顿后显示”的下一轮联想，而不是让联想条持续常驻。
- 联想由两层合并：持久化的用户上下文转移记录优先，内置 65,536 条汉字边界二元模型负责冷启动回退，全程不发起模型请求、不消耗 Token。
- 用户联想记录采用内存热查询与独立 SQLite 串行写入，输入热路径不访问数据库；重新启动输入法后记录仍可恢复。
- Session、`InputConnection` 身份、光标上下文与候选 revision 四重校验会拒绝陈旧点击，避免切换输入框后把旧候选写入新编辑器。
- 密码输入框禁用上下文读取；带 `IME_FLAG_NO_PERSONALIZED_LEARNING` 的编辑器不读取或新增用户联想，只保留静态本地回退。

## 验证与发布

- 新增候选排序、退格/整词替换、启动期学习重放、异步 selection 回执、QWERTY/T9 现代词覆盖、上下文联想、二元后继枚举、持久化恢复、陈旧候选隔离、延迟唤起/取消/超时状态机，以及联想条与工具栏互斥布局回归测试。
