## ChatGPT / Codex OAuth

- Codex 订阅登录从设备码轮询切换到浏览器 Authorization Code + PKCE。
- Sense 会先绑定 loopback `127.0.0.1:1455`，再打开 ChatGPT 登录页；授权完成后浏览器自动回调，无需复制代码。
- PKCE S256、随机 state、回调 state 校验、五分钟总超时、显式取消和页面销毁均纳入同一登录生命周期。
- 刷新令牌继续只保存在 Android Keystore 支持的凭据 Vault；登录 URL、authorization code、PKCE verifier 和 token 不写入设置、日志或错误信息。
- OAuth 参数和 localhost 回调形态对齐当前 OpenAI Codex，并参考 jcode 的浏览器登录实现。

## Agent 远程信道

- 新增窄接口 `AgentChannelAdapter`，将平台连接、标准化入站、发送、流式编辑与连接状态从 Agent 核心分离。
- Telegram 使用 Bot API `getUpdates` 长轮询，持久化 update offset，断线采用有界指数退避；结果通过 `sendMessage` + `editMessageText` 原位更新。
- 飞书/Lark 使用官方 Java SDK 的 WebSocket 长连接与 normalized message API；无需公网 webhook，支持中国站和国际站。Sense 关闭 SDK 默认消息合并，并用容量 32 的单一 admission lane 串行写入 Journal。
- 设置页提供独立信道入口。Bot Token 和 App Secret 进入 Android Keystore；非敏感配置使用原子文件和跨进程文件锁。
- 每个信道首次使用六位 `/pair` 绑定指定 peer/chat；code + generation 在文件锁内 compare-and-bind，重置会立即换码并重载后台服务，旧 callback 不会重新绑定。
- 支持 `/status`、`/stop`、`/new`、`/help` 与 Agent 目标目录命令。通知栏提供持久“暂停信道”，设置页提供显式恢复；Agent 任务本身也始终保留独立停止入口。
- 本版实际可执行目标只有本机 `sense`；Telegram 与飞书共享当前 Sense Hub 会话。远端 Agent target 与按信道隔离的外部 conversation id 已在 ADR 0027 固定接口和迁移顺序，本版不把扩展槽写成已连接能力。
- 前台服务运行在 `:brain` 并采用 `START_STICKY`，与 Agent Hub 前台管理共用 runtime；用户启用且未暂停时才在开机完成后恢复。设置页状态查询本身不启动服务，连接状态、队列长度、认证错误和配置 revision 通过包内广播回到主进程。
- 输入法 `:ime` 通过私有 Hub Bridge 控制 `:brain` 唯一 runtime：Binder transaction 全部从专用 writer 线程以 `FLAG_ONEWAY` 发出，命令使用异步 ACK、command-id 去重和重连 fence，IME 主线程不等待 Binder。首个 projection 采用小于 256 KiB 的有界 wire 与 latest-wins backpressure，随后按 cursor 自动分页回填 Hub 保留的全部 80 条消息、40 个归档及当前会话；单页消息和会话目录也各自保持小于 256 KiB。Binder death 重绑后会丢弃旧连接回调。
- 入站消息先写入崩溃安全 Journal，再由 Agent 消费。Journal 保存幂等事件 ID、Telegram offset、活动 run 关联和会话内 target 选择；队列满时 Telegram 不推进 offset，飞书不完成 callback，不静默覆盖旧消息。
- Prompt 以 PREPARED/ACTIVE 两阶段关联 exact run identity；恢复只复用同一 PREPARED identity，ACTIVE 缺失运行证据时不重复执行。
- 远端回复采用节流的流式 edit；send/edit 记录最后成功文本，最终文本未变化时复用 remote id。Telegram 长回答使用 surrogate-safe 分块，Journal v5 逐块保存 remote id，崩溃后从未确认分块继续。只有全部最终分块确认后才完成 Journal 事件，失败保留 pending 状态并有界退避。
- 配对/重置/暂停均递增配置 revision；设置页即使正处于初次慢读取，也会在新 revision 到达后补做一次读取。认证失败保持 ERROR，部分信道可用显示 DEGRADED，不会把重试误显示为全绿运行；poll/connect/send/edit 的致命认证错误会关闭对应 adapter、终止其队头并释放其他信道。
- disable/pause 保存后，旧连接在执行每条消息前都会重读最新设置并停止分派。reload 后，已禁用信道遗留的 active/FIFO 头写入 Journal terminal failure ledger 并释放全局队列，不会继续堵住另一个仍启用信道。

## 候选展开连续滚动

- 删除候选分页、页码和上一页/下一页控制，展开区改为单一纵向 content-space 网格。
- 复用 `ContinuousVerticalScrollState`、`VelocityTracker` 与 `OverScroller`，支持逐像素拖动、惯性和边界收敛，不再以滑动手势触发整页跳转。
- 绘制路径二分定位首个可见行，在 viewport 内 clip/translate，只绘制可见候选；比例滚动条不在动画帧创建候选集合。
- 命中测试将屏幕坐标映射回内容坐标，始终返回原始全局候选索引。
- 候选 revision 变化、列表缩短、收起或切换面板都会终止旧 fling、取消冻结触点并约束 offset。
- 折叠候选条继续使用原有横向连续拖动与 settle 行为。

## Sense Mic

- Android 设置页新增可独立启停的麦克风前台服务，提供发现、配对、加密传输和运行状态。
- 音频链路为 48 kHz 单声道 PCM → Opus，包含序列号、FEC、jitter buffer、PLC、心跳和自动重连。
- Rust `sense-mic-client` 支持 Windows 与 Linux；Linux 可创建 PipeWire/Pulse 虚拟源。
- Windows 端包含可复现构建的 x64 WaveRT `Sense Mic Playback -> Sense Mic` 虚拟音频驱动工程和测试签名打包脚本。
- GitHub Release 的 Windows 压缩包内含 Rust Client 与测试签名 WaveRT 驱动；Linux 压缩包内含 x64 Client、使用说明、许可证与 NOTICE。
