# Sense 设置页改版：Agent 管理与 Skills 工作台

状态：开发准备稿，基于 v0.4.16 正式版源码审计；本轮不将新版 UI 混入正式 APK。

## 1. 产品边界

**输入法前端是 Agent 的使用现场，设置页是配置和管理入口。**

输入法工具栏中间的 Agent 入口、对话、终端/浏览器运行预览、可收起的内置输入框、
面向外部编辑框的操作仍留在 IME View 内。打开设置只改变观察者和配置，不改变任务所有权。
退出设置、收起输入法、离开对话均不等于停止任务；停止必须有清晰、独立且随时可达的操作。

本次重点不是换颜色，而是减少首次使用的步骤、让能力与运行状态可理解、让创建 Skill 有明确回报。
保留用户已有模型配置、凭据、Skill ID、修订历史、键位绑定、草稿及完整会话记录。

## 2. 当前代码审计

以下是源码结论，不冒充新一轮截图验收或用户可用性测试。

| 当前实现 | 问题 | 保留/调整方向 |
|---|---|---|
| `SettingsActivity.renderHome` 顺列十个分类，含 Provider、Soul、工具、信道、Action Skills、Skills | 用户要自己理解模块关系；已启用后仍展示大块启用/切换按钮 | 归并四个一级分区，首页以状态摘要和常用入口为主 |
| `SettingsNavigationState` 只有 current/parent，恢复时 parent 回 HOME | 新编辑流程超过两级时，返回和旋转恢复容易丢失位置 | 引入带参数的可序列化 route 栈，旧 section 深链继续映射 |
| `ProviderSettingsScreen` 已有服务预设、浏览器 OAuth、连接测试、自动保存和高级折叠 | 不是缺登录能力，而是模型、认证、能力状态分散，首页缺摘要 | 复用现有控制器；区分“已保存”“已连接”“上次测试时间” |
| `AgentToolsSettingsScreen` 是总开关加八个开关 | 终端/浏览器是否就绪、所需前提、最近失败不可直观看到 | 能力分组列表，每项进入详情；禁用总开关不覆盖单项偏好 |
| `renderSoul` 目前主要是三段说明 | 宣称有记忆，但用户缺少查看命中来源/记录范围的管理入口 | 第一阶段只读检索与证据详情，保留全部原始记录 |
| `SkillsSettingsViewFactory` 在同一 View 中放选择器、模板、身份字段、指令、键盘、操作和历史 | 长表单，查看一个技能也需要经过编辑区；主要动作淹没在多个全宽按钮里 | 列表、详情、编辑、绑定四个独立状态，逐步呈现 |
| 已有 `SkillKeyboardBindingPicker`、草稿控制器、修订与冲突处理 | 这些已实现，重做外观时容易误删可靠性能力 | 沿用状态/持久化层，重做呈现；键盘绑定成为独立可复用面板 |
| `ActionSkillsSettingsScreen` 只展示内置描述符和启用开关，当前注册黄金报价 | 与普通 Skills 割裂；凭据仓库已有能力，用户入口尚薄弱 | UI 统一目录，执行后端分型，补连接配置/试运行/结果映射 |
| Action 开关保存失败后移除监听器且未重新注册 | 此次失败后同页再次操作可能不再保存 | 列入独立修复，用状态驱动重绘并添加失败后重试回归 |
| `AgentChannelsSettingsScreen` + `agent_channels_body` 是“外部消息进入本机 Sense”的接入模式 | 名称容易被理解为 Sense 控制远端 Agent | 明确写“允许外部访问 Sense”；另一方向独立建“控制远程 Agent” |

当前分支未检索到 TDLib / MTProto / 飞书 `user_access_token` 的用户端控制实现。
这只描述本次审计的代码，不覆盖其他工作分支的开发状态；实现该入口前先核对、合入已有对应实现，
不要把 Bot Token 接入界面包装成用户身份客户端，也不要删掉现有受控端能力。

## 3. 信息架构

```text
Sense 设置
├─ 首页：输入法状态、Agent 状态摘要、最近使用 Skills
├─ 键盘：输入方案 / 外观与高度 / 候选与个人词库 / 语音
├─ Agent：模型与账号 / 工具能力 / 记忆与记录 / 远程连接 / 后台任务
├─ Skills：全部 / 常用 / AI 指令 / API 动作 / 草稿
└─ 更多：Sense Mic / 数据导出与诊断 / 关于
```

小屏采用“首页、Agent、Skills、更多”四个底部目的地，键盘是首页首个固定入口。
详情页显示明确返回键和短标题，编辑时隐藏底部导航，保留单一底部操作区。
首页正常状态收紧为一行“Sense 已启用 · 当前输入法”；未启用才展开引导，不反复占据首屏。
设置搜索仅检索标签、说明与 Skill 元数据；搜索历史、任务和原始记忆另用明确入口。

旧入口兼容：PROVIDER/TOOLS/SOUL/CHANNELS 映射到 Agent 子路由；ACTION_SKILLS 映射到 Skills 的 API 过滤器；
SKILLS 保留直达目录。已打开的 Skill 恢复到 ID 和草稿版本，而不是 Spinner 的下标。

## 4. 视觉方案

沿用 Sense 蓝色辨识，不引入巨型渐变 Hero、成排描边卡片、Emoji 图标或每行一个主按钮。

- 背景浅灰蓝，卡片实色白；正文接近黑，辅助信息灰色，蓝色仅用于选中/主要动作。
- 统一 4/8 dp 间距网格，页面边距 20 dp；分组间距 24 dp，卡片内边距 16 dp，圆角 16 dp。
- 顶栏标题 22 sp，页面标题 26 sp，条目标题 16 sp，正文 14 sp，辅助信息 12 sp；行高随字号增长。
- 单色矢量图标；所有状态同时含文字，不仅用红/绿点区分。
- 普通条目最小高 56 dp，点击目标至少 48 dp；标题支持两行，不用固定高度截断大字体。
- 一屏只有一个显著主操作；危险或低频操作放溢出菜单，详情页再确认影响范围。
- 200% 字号时改为垂直排布，底部动作区可增长；横屏/窄高窗口不锁死编辑器行数。
- 深色资源单独定义对比度；不把当前半透明 `sense_surface` 原样叠到所有背景。

首页示意：

```text
Sense                                      搜索
已启用 · 当前输入法                    管理 ›

键盘与输入                       全拼 · 26 键 ›

Agent                         模型已配置    ›
当前无任务 / 正在运行 · 查看与停止
模型与账号        工具能力        记忆与记录

我的 Skills                              全部 ›
润色文字         AI 指令 · A↑

首页           Agent           Skills        更多
```

首页不请求模型、启动终端或拉起浏览器。摘要读取异步快照；“已配置”与“连接正常”不是同一状态。

## 5. Agent 管理

### 5.1 概览和模型

首屏显示：当前模型名称、账号状态、任务状态，以及“模型与账号 / 工具能力 / 记忆与记录 / 远程连接”。
模型选择沿用现有 Provider 预设，OAuth 继续浏览器登录；只在 API Key 方式显示密钥输入。
默认折叠 URL、协议样式、流式和推理参数，避免第一次打开就出现一整页工程字段。

连接测试是显式动作，能取消、显示耗时和错误类别；测试旧版本配置的结果不得盖过新输入。
有效配置更改自动保存，显示“保存中/已保存/保存失败”；无效的暂存字段不替换可用配置。
凭据只显示“已保存/待登录/已过期”和删除入口；日志、截图、草稿快照及普通导出不含密钥。
首期仍尊重当前单 Profile 数据结构，多账号/多模型 Profile 属后续独立迁移。

### 5.2 工具能力

按“网页与浏览器 / 终端与文件 / 记忆与 Skills / 计算与编辑”分组。
一行包含名称、简短用途、配置开关和就绪状态：已关闭、待准备、可用、上次失败。
点详情再展示环境、边界、最近错误和显式自检；打开详情本身不执行命令或访问网页。
不存在的能力不画可点击的假开关；编辑能力详情明确依赖当前 IME 编辑框，而不是设置页 EditText。

### 5.3 后台任务与 IME 协同

- 设置只通过 `AgentHubPort` / 既有跨进程客户端订阅投影，不持有 WebView、终端进程或模型调用。
- IME 左下角实时预览继续使用同一工具运行投影；收起预览只移除 View 观察，不停止任务。
- 运行卡片显示任务名、状态、最近工具；主操作是“查看进度”，次操作是“停止本任务”。
- 停止命令包含 runId；运行中→正在停止→已停止，收到运行端确认才显示终态，防止误停后来启动的新任务。
- 退出设置仅取消连接测试、释放观察者，保留已经接受的持久化写入；不调用全局任务 shutdown。
- 前台服务通知保留查看/停止入口；Android 进程回收、服务异常和网络中断要标成“已中断/待恢复”，
  不把投影失联显示成“仍在运行”，也不承诺进程被杀后网络执行仍继续。
- 恢复界面重新取运行状态，不按过期的 View 状态重发 API、重复发送消息或再次执行有副作用的工具。
- 打开设置后旧外部 InputConnection 不再作为上屏目标。回到 IME 后重新校验编辑器代次、焦点和选择范围；
  设置中的试运行默认只预览，不自动写入设置字段或先前 App。

### 5.4 记忆与远程连接

记忆第一页先展示原始会话、事件索引、Action 调用记录的真实数量和状态，再提供搜索。
每个命中可展开原始证据、所属会话、时间及命中范围；扫描被截断必须显示。事件索引不替代原始会话。
未查询、无命中、索引处理中、读取失败分开呈现。重建索引保留原始记录，删除/导出后续做独立流程。

远程连接显式分两组：

1. **控制远程 Agent**：以用户账号向远端会话发消息；按账号+平台+对话 ID 隔离未读、草稿和历史。
   接入已实现用户端适配器后才标记可用；UI 消费统一会话投影，不直接持有 Telegram/飞书网络连接。
2. **允许外部访问 Sense**：保留现有 Bot/应用接入、配对、暂停与解除绑定。名称、方向图和凭据表单都与第一组区别。

## 6. Skills：从“编辑配置”变成“挑一个能力来用”

### 6.1 统一技能库

使用可回收列表，稳定 ID，支持名称/描述搜索和类别过滤。避免把所有技能编辑器一次创建出来。
卡片只显示名称、一句话用途、类型、键位绑定和可用状态；最近使用数据缺失时省略，不伪造计数。
“AI 指令”注明调用模型，“API 动作”注明“0 模型 Token”，并说明 API 自身可能计费；
AI 生成一个 API Skill 的创建步骤与以后直连执行的成本分开显示。

首屏主操作为“新建 Skill”。空状态提供“翻译 / 润色 / 总结 / 获取数据”模板，不要求先填 ID。
内置技能以“复制后编辑”开始，保留原始内置定义和用户修订的区别。

### 6.2 创建流程

```text
选择类型/模板 → 名称与行为 → 用样例试一下 → 保存 → 可选绑定键位
```

AI 指令的最小表单只有名称和“希望它做什么”；简介、基础编辑意图和完整 Markdown 放高级区。
ID 自动生成且稳定，重命名不换 ID，高级区可查看；模型帮助编写属于用户主动触发的单独功能。
模板同时提供一条可替换的测试输入。试运行清楚标记是否调用模型，显示过程、结果、取消及失败重试。
运行使用独立测试上下文，不向当前外部编辑框写入，不把样例当作用户长期事实自动记忆。

编辑底部固定“试运行 / 保存”，正文区真正随键盘缩放滚动；不要使用两行的固定编辑高度。
返回自动保留草稿并给出“草稿已保留”；显式丢弃只删除当前草稿。保存失败保留输入，恢复后可重试。
“保存并绑定”必须在持久化成功后继续绑定；取消绑定仍保留已保存 Skill。

### 6.3 绑定键位

复用已有键盘模型，独立面板显示当前布局、被占用槽位、选中 Skill 与手势方向。
点键→选上/下/左/右手势→看到“长按 A 后上滑：润色文字”→确认。
覆盖已有绑定时明确展示被替换技能；取消则不改任何绑定。
提供等价的可访问列表选择入口；26 键缩略图每键受窄屏限制，列表入口保证无需精确点中小热区也能完成绑定。
不抢占保留的系统手势；可用槽位必须来自生产键盘策略而非 UI 自己硬编码。

### 6.4 API 动作和认证

首期复用现有 `DirectActionSkillRuntime` 与黄金报价描述符，增加“测试连接、最近结果、绑定/快捷入口”。
统一的是目录与交互，不是把 API 运行绕回 LLM，也不是立即把两套持久化格式强行合并。

下一增量的自定义 API 向导：

1. 选择模板，或填写 HTTPS 地址；展示方法、变量、超时和输出样例。
2. 认证：无 / Bearer / 指定 Header API Key，选择已有连接或新增连接；按域名/连接器约束凭据使用。
3. 点“测试请求”，显示状态码、耗时、经过脱敏的 JSON 与可选择的字段。
4. 点击字段生成结果卡和插入模板；校验必需字段、类型、空值、数据时间及单位。
5. 保存动作并按需绑定。由键位、快捷项或确定性命令路由触发时直接调 API，整个执行路径不创建模型请求。

首期限定 GET 数据查询；更复杂的请求体、有副作用的动作和 OAuth 连接器另行实现并验证。
凭据仍走 `AndroidActionCredentialVault` 的 Keystore 加密和句柄租用；模板/分享文件只保存引用及占位字段。
重定向到另一主机时剥离认证头，拒绝未获凭据授权的新目的地；自定义端点输入验证与大小限制由运行层执行。
401/403 显示“认证待更新”，429 按服务端策略退避；测试取消和设置关闭不遗留重复请求。
黄金报价时间缺失/陈旧时展示取数时间与数据时间的区别，不把缓存或未知时间标作实时。

### 6.5 版本与运行记录

技能详情提供“编辑 / 试运行 / 绑定”，更多菜单收纳复制、历史和停用。
版本历史沿用现有 revision 及冲突检查；恢复旧版本生成新修订，不悄悄抹掉中间记录。
每次运行引用 skillId+revision，后续编辑不改变运行中任务的快照。
试运行记录与正式调用分区呈现，普通列表只显示脱敏摘要，完整原始证据仍由既有记录层管理。

## 7. 工程拆分与可靠性约束

第一阶段继续使用 Android 原生 View 及现有控制器，不为外观一次性迁移 Compose 或重写 runtime。

| 开发切片 | 主要落点 | 完成标准 |
|---|---|---|
| S1 设置外壳 | SettingsActivity、SettingsNavigation、SettingsViewFactory、颜色/字符串资源 | 四目的地、真实摘要、旧深链兼容、返回栈与滚动恢复；此阶段不改存储 |
| S2 Agent 概览 | 新 AgentSettingsScreen + 现有 Provider/Tools 控制器 | 配置/连接/运行状态区分，生命周期不取消正式任务，停任务有确认终态 |
| S3 Skills 列表与详情 | 新 SkillLibraryScreen / SkillDetailScreen；SkillSettingsRepository 适配 | AI/API 统一只读目录，稳定 ID、过滤、空/错/加载状态，旧数据零丢失 |
| S4 创建与绑定 | SkillsSettingsScreen、ViewFactory、Draft/Mutation/History 控制器、KeyboardBindingPicker | 模板→编辑→试运行→保存→绑定闭环；草稿/冲突/修订回归全过 |
| S5 API 连接配置 | ActionSkillsSettingsScreen、ActionSettingsStore、CredentialVault、DirectActionRuntime | 内置动作测试和凭据入口；自定义 GET 注册为独立后续增量，明确真实能力状态 |
| S6 记忆和远程管理 | 现有记录投影/跨进程端口 + 已验证的远程适配器 | 证据可追溯、两种信道方向不混淆、失联/重连/停止可辨认 |

UI state 与 Android View 分离，所有加载/保存结果携带路由实例和数据修订号；过期回调丢弃。
配置开关保存采用有序写入和实际提交值回显，失败后保留重试监听器；不将“点击已接受”等同“已保存”。
底层 Agent 会话和普通输入核心模块边界不动，界面改版不引入 IME 网络依赖。

统一目录最小投影示意（不是本轮已实现 API）：

```kotlin
data class SkillSummary(
    val id: String,
    val kind: SkillKind, // AI_INSTRUCTION / DIRECT_ACTION
    val revision: String,
    val name: String,
    val summary: String,
    val bindings: List<BindingSummary>,
    val availability: Availability,
    val draft: Boolean,
)
```

由适配层聚合现有 AgentSkillCatalog 和 ActionSkillDescriptor，后端继续分开存储。
S1–S4 是首个设置改版交付；S5/S6 只在运行层能力真实到位后开放对应操作。

## 8. 验收清单

仅使用专用模拟器；不操作实体手机。新 UI 必须留截图和操作证据，而不只通过 JVM 测试。

- API29 与较新 API，360/411 dp 宽度、横竖屏、浅/深色、100%/200% 字号；焦点与操作按钮不被软键盘遮挡。
- 从 IME 进入任一设置子页，系统返回/应用返回/旋转/进程重建后位置与草稿恢复；旧 section 深链可用。
