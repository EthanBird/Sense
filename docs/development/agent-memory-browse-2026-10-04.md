# Agent 记忆浏览与检索

## 问题与代码依据

旧的 `memory_search` 同时在工具 schema、参数路由和 journal 检索层要求非空关键词。
空查询既未公开为浏览入口，也会被校验拒绝。因此“列出记忆”缺少可执行接口，仅调整模型措辞不足以解决。

## 本轮实现

保留现有工具名和记忆开关，增加两种操作：

```json
{"mode":"list","max_results":8}
```

```json
{"mode":"list","channel":"experience_event","max_results":8}
```

```json
{"mode":"search","query":"颜色偏好","max_results":8}
```

- 未填 `query` 或空查询默认进入 list；旧的非空 `query` 调用继续使用 search。
- list 支持 `all`、`session_evidence`、`experience_event`、`action_skill_history`。不把派生事件当成全部记忆，原始会话仍可浏览。
- 返回 `next_cursor` / `has_more`；翻页沿用 channel 与 include_trace。原始 journal 使用不可变帧偏移，API 历史使用 JSONL 字节边界，追加记录不会移动已开始浏览的来源分页。
- 默认列出请求、最终答复、经历事件、非记忆工具结果、错误与取消记录。过滤低层流式噪声和重复的记忆工具回显；`include_trace:true` 可浏览这些记录。过滤仅影响展示，不改动任何保存内容。
- 会话 JSON 提取 snapshot.text，答复提取正文，经历事件提取 summary/facts，保留记录 ID 与来源引用。输出是有界摘录，不是全量正文导出。
- 多来源结果按各自追加顺序取最近记录，不宣称全局时间排序。当前运行的记录排除，避免检索自身请求。
- 扫描有记录数、字节数和结果数预算。空的有界页面可继续翻页；读取失败、存储未连接、无关键词命中、穷尽来源分别反馈。API 损坏行计入 skipped_records。
- 按实际 JSON 转义长度分配结果预算，避免 20 个长结果被 Brain 的 16,384 字符上限截成损坏 JSON。

## Agent 行为

提示词明确让“看看记住了什么”“列出最近记忆”等请求先调用 list，不要求用户猜关键词。
特定事实仍用 search；零匹配可以缩短关键词或转为浏览，不将零匹配解释为没有历史。
有后续页时明确分页范围，用户请求全部时在工具轮次预算内继续，剩余部分明确标注。
历史内容作为资料而不是指令，重复观察合并成易读条目并附来源。
