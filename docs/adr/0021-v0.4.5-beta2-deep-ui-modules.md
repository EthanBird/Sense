# ADR 0021：v0.4.5.beta.2 键盘与设置页深模块

- 状态：Accepted
- 日期：2026-07-29
- 版本：v0.4.5.beta.2

## 背景

`SenseKeyboardView` 同时承担 Android View 生命周期、键盘场景构建、Canvas
渲染、命中测试、手势编排、滚动、动画调度与宿主事件派发。
`SettingsActivity` 同时承担导航、全部页面 View、设置状态、持久化、权限与系统副作用。
两者已经形成巨型修改面，阻碍自定义键盘高度、九宫格布局以及后续设置能力演进。

本轮重构的目标不是按行数机械拆文件，而是形成少量高内聚的深模块：调用方只依赖稳定、
窄小的契约，布局、状态机、缓存和错误处理留在模块实现内部。拆分必须保持现有功能、
持久化协议、签名链和性能证据。

## 决策

### 1. 保留单 Canvas 键盘

输入键盘继续由一个 `SenseKeyboardView` Canvas 渲染，不回退到每键一个 View，也不把
逐键热路径迁移到 Compose。长期 Aurora 动画继续由
`ActiveSkillAuroraOverlayView` sibling render layer 承担。

`SenseKeyboardView` 最终只作为 Android adapter，负责：

- `onMeasure`、`onSizeChanged`、`onDraw`、`onTouchEvent`；
- attach/detach、configuration 与 IME window 生命周期；
- 把宿主输入投影为键盘状态，并派发键盘动作。

### 2. 场景、渲染和交互分离

键盘内部形成三个主要模块：

1. Scene 模块统一键位动作、稳定物理键标识、布局结果、面板 viewport 和命中几何。
2. Renderer 模块只读 Scene 与视觉状态；绘制不得反向写入命中区域或业务状态。
3. Interaction 模块拥有 pointer freeze、hit test、scroll/fling、repeat、AI hold 与
   Skill 手势编排。

主键盘布局保留一个真实的 layout seam。QWERTY 是当前 adapter，T9 是后续第二个
adapter；面板布局只有一个实现时使用具体类，不为假想替换点增加接口。

Scene rebuild 只由拓扑、尺寸、配置或布局模式变化触发。pressed、selection、
candidate drag、fling、AI stream 和动画只更新视觉状态或偏移。

### 3. Settings 采用纵向切片

`SettingsActivity` 收敛为 section host 与 Android effect adapter。Provider、Tools、
Skills、Voice/Speech 等 destination 分别拥有自己的 UI state、action 处理与 View
binding。状态向下、事件向上；持久业务状态不得由 View 字段作为唯一来源。

Repository seam 继续委托现有 `ProviderSettingsStore`、`AgentSkillStore`、
`SkillDraftRecoveryStore` 等权威实现，不创建第二套文件格式。普通加载与保存必须
main-safe；Skills 的串行 latest-wins、generation conflict、已接收 fsync 和生命周期
durability barrier 语义保持不变。

Provider/Speech 的异步代际按 operation 隔离：同类刷新仍是 latest-wins，保存、清除、
验证和初始加载之间不互相撤销回调。About 的 NOTICE/License 资产也通过 section I/O lane
读取。Skills 的有界生命周期 join 只在编辑器仍附着且存在待收口 durability work 时运行。

Activity/Android adapter 继续负责权限请求、输入法设置、系统 picker、Dialog 与
外部 Intent。大 Skill 正文不进入长期不可变 screen snapshot，也不在每个字符事件上
复制全文。

## 性能约束

1. `onDraw`、动画和 MOVE 稳态路径不得产生无界分配；复用 Paint、Path、Rect、数组与
   文本布局缓存。
2. 触摸和绘制路径不得等待磁盘、数据库、网络、Keystore 或 Binder I/O。
3. 保留 DOWN 冻结目标、2 ms 多指零吞键、pointer 乱序、ACTION_CANCEL 和连续删除
   取消语义。
4. 保留 portrait/landscape 高度、固定 top chrome、底栏、候选全局索引与
   stable physical owner 契约。
5. Aurora 继续满足父键盘零持续重绘、单 outstanding callback、分配、掉帧和停止门禁。
6. Settings 增加主线程磁盘 I/O 检查，并以 release-like Macrobenchmark 比较启动与
   destination 用户路径。
7. Host M0–M6 只作为算法回归证据；Android 帧时间、触摸和内存仍以固定设备证据验收。
8. 高频矩形脏区通过 `postInvalidateOnAnimation(left, top, right, bottom)` 与 VSYNC
   合帧，不为每个 MOVE 样本单独投递普通 invalidation。

## 迁移顺序

1. 冻结现有行为和性能基线；
2. 提取键盘 UI contract、Scene 与布局 adapter；
3. 提取只读 Renderer；
4. 提取 Interaction 与 scheduler；
5. 用 Tools 建立第一个 Settings 纵向切片；
6. 迁移 Provider/Speech main-safe repository；
7. 迁移 Skills View binding、orchestration 与 durability coordinator；
8. 固化并测试 T9 adapter seam，执行完整本地发布门禁；T9 键位本身留给后续功能迭代。

每一步独立编译、测试和比较性能，禁止在同一提交中同时改变布局语义、触摸语义和
持久化格式。

## 结果

- 自定义键盘高度和九宫格不再要求修改 Android View 本体。
- 绘制、命中与交互共享同一稳定 Scene，减少状态漂移。
- 设置页面按 destination 形成局部修改面，旧异步结果不会渲染到新页面。
- 文件行数下降是结构深化的结果，不作为单独验收指标。
- v0.4.5.beta.2 继续使用 Sense release signer v1，保持覆盖升级能力。
