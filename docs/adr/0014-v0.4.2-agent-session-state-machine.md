# ADR 0014：v0.4.2 Agent 会话状态机、多轮公开反馈与新工具箱

- 状态：Accepted for `v0.4.2`
- 日期：2026-07-25
- 关联：[`ADR 0012`](0012-v0.4.0-interruptible-ai-and-speech-surface.md)、
  [`ADR 0013`](0013-v0.4.1-bounded-stream-and-system-speech-recovery.md)

## 背景

`v0.4.1` 已具备长按空格、上滑锁定、流式预览、一次有界恢复与右下停止，但真机反馈指出：

1. 锁定手势有时会把已经进入理解或生成的会话重新显示成笼统的“正常生成”，主区域为空；
2. Brain 的 `CONNECTING / UNDERSTANDING / GENERATING / VALIDATING` 状态粒度不足，无法表达
   模型公开更新、原生工具开始与结束、本地校验和编辑器写入；
3. 单次模型请求虽然会流式输出，却不是 Hermes 式“模型提交进度、Harness 返回真实工具结果、
   模型继续工作”的多轮 Agent；
4. 锁定后已有显式停止键，15–30 秒的旧流空闲窗口会过早终止仍在正常思考的模型；
5. `v0.4.1` 的 3 × 2 大卡片工具箱信息密度低、边框重，与键盘本体割裂。

本设计借鉴 Hermes 在消息平台中原位更新状态、公开工具活动并保持会话可取消的交互原则，而
不复制其终端 UI，也不把私有 chain-of-thought 暴露到键盘。参考：

- [Hermes Agent](https://github.com/NousResearch/hermes-agent)
- [Hermes Telegram integration](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/messaging/telegram.md)
- [Hermes messaging gateway](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/messaging/index.md)

## 决策

### 1. 执行状态与手势锁定彻底分层

每个 Agent run 由 `AgentSessionStateMachine` 管理：

`CREATED → CAPTURING → CONNECTING → UNDERSTANDING → THINKING → TOOL_RUNNING /
DRAFTING → VALIDATING → APPLYING → COMPLETED`

网络或协议校准进入 `RECOVERING`，用户停止进入 `CANCELLED`，不可恢复错误进入 `FAILED`。
状态机使用显式转移表，拒绝身份不符、终止后迟到和非法倒退事件。

按住、上滑进度、锁定和停止属于控制平面。锁定只把手势所有权从“松手取消”改为“松手继续”，
不向执行状态机发送重置事件，不清空活动行、状态文案或预览。

### 2. 公开活动使用稳定 step，而不是拼接日志

`AiEvent.AgentProgress` 包含：

- 单调 `revision`；
- 可重复更新的 `stepId`；
- `kind`、`state`、短标题和可选短详情；
- 工具事件的 `toolCallId` 与 `toolName`。

键盘仅展示最近几项活动，并按 stable id 原位更新 `RUNNING / COMPLETED / FAILED`。本地心跳
每 2.5 秒更新一个固定 step，显示等待时长；心跳、观察和恢复提示不算远端 socket 活动，
因此不能推迟首事件或流空闲 watchdog。

公开内容只允许一行、受长度和 Unicode 门禁约束。API Key、输入原文、工具参数、模型私有
推理和原始 Provider 错误正文均不进入活动事件。

### 3. DeepSeek 使用真实的有界 Agent 多轮

官方 DeepSeek Chat Completions 原生工具路径提供两个工具：

1. `sense_report_progress`：非终止工具，只接受一条安全公开更新；
2. `sense_submit_patch`：唯一终止工具，提交 `sense.editor.patch.v1`。

模型每个 assistant turn 只能调用一个工具。Brain 收到进度工具后先校验参数和 call id，
发布公开更新，再向 Provider 回放真实 assistant tool call 与本地 tool result，启动下一轮。
最多接受两轮公开进度；随后只提供终止工具，防止模型无限汇报而不完成任务。

DeepSeek thinking mode 的后续工具轮按官方要求回放该轮 `reasoning_content`。该值只保存在
隔离 Brain 的有界内存中，既不通过 Binder 发送，也不进入日志或 UI。普通 assistant 文本
仍无编辑权限。

参考：

- [DeepSeek thinking mode](https://api-docs.deepseek.com/guides/thinking_mode/)
- [DeepSeek tool calls](https://api-docs.deepseek.com/guides/tool_calls/)
- [DeepSeek API updates](https://api-docs.deepseek.com/updates)

### 4. 预览和写入仍是两套权限

多轮反馈不会绕过既有 Harness：

- 活动、description 和 preview 都只有展示权；
- 终止 Patch 必须通过 schema、request/generation、snapshot、hash/CAS 和目标范围校验；
- IME 在写入前重新读取宿主状态，原子执行计划并进行写后验证；
- 取消、锁定会话的停止、输入框变化和 Brain 死亡会先撤销本地 authority，再中断网络；
- 空白中间帧不能覆盖已有非空预览。

### 5. 停止优先，但保留硬安全上限

普通会话默认时间预算调整为：

- 连接：15 秒；
- 首个 Provider 事件：45 秒；
- 流空闲：120 秒；
- Harness 绝对上限：300 秒。

停止按钮仍即时撤销 generation 和编辑 authority。绝对上限用于断网、Provider 永久挂起或
回调丢失等失控场景，不因心跳、工具轮或恢复而延长。连通性测试继续使用更小预算，避免
设置页测试意外消耗过多 Token。

### 6. 工具箱改为图标控制中心

工具箱使用四列首行加居中的两项次行。每项采用独立的彩色图标底座与简短标签，面板背景
沿用键盘底色，不绘制六个笨重外框。整个几何 slot 都是命中区域，视觉间距不会形成点击
死区。“先思首页”直接打开设置 App 首页。

## 验证

自动化覆盖：

1. 状态机合法转移、非法倒退、终止后迟到、工具 call id 开始/完成配对；
2. 心跳可见但不能延长 Provider watchdog；
3. DeepSeek 进度工具、真实第二轮、私有 reasoning 回放和唯一终止 Patch；
4. Binder 编解码、Surface 活动映射、锁定不重置、非空预览保持；
5. 工具箱 4 + 2 几何、入口路由和横竖屏边界。

仓库另含显式启用的 `LiveDeepSeekAgentProbeTest`。它从进程环境读取临时 Key，不打印 Key、
输入正文、模型结果或私有推理，并使用生产 `HttpUrlConnectionProviderTransport`、
`AiBrainEngine`、流解析器和本地协议门禁。2026-07-25 的开发验证使用
`deepseek-v4-pro` thinking mode 完成：约 35.6 秒、60 个事件、28 个公开进度更新、4 个工具
状态更新、1 个终止 Patch；Key 未写入仓库或测试产物。

真实 Provider 探针不能代替 Android 移动网络、代理切换、长文本、后台/前台切换和不同宿主
输入框的真机验收。普通 CI 不持有用户 Key，因此默认跳过该测试。

## 版本与后续

本次版本为 `versionCode 17`、`versionName 0.4.2`、tag `v0.4.2`。`0.4.x` 继续完善 AI；
工具能力、长期会话、Provider 差异和真机稳定性达到既定门禁后再升级到 `0.5.0`。
