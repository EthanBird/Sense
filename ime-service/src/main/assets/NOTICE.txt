Production lexicon transformation
---------------------------------

ime-service/src/main/lexicon/sources.json is the canonical production source
manifest. It pins source revisions, byte hashes, license boundary, accepted
formats, rational weight transforms, length bounds, and per-index thresholds.
tools/lexicon_sources.py verifies that each relative path remains beneath the
manifest root and that its SHA-256 matches before parsing any entry.

The build retains Rime Frost pinyin and corpus frequency columns. The core and
single-character sources retain their weight scale; the long-tail ext source
uses a manifest-pinned 3/4 multiplier and others uses 4/5. Zero-frequency rows
receive a small source-specific floor rather than placing the whole supplemental
dictionary in one weight=1 bucket. All transforms use integer arithmetic.

The normalized attributed IR records text, syllable-separated pinyin,
calibrated weight, tier, source id, raw weight, and index eligibility. It is
generated by:

python tools/build_pinyin_lexicon.py \
  ime-service/src/main/lexicon/sources.json \
  ime-service/src/main/assets/pinyin_lexicon.bin \
  --manifest \
  --canonical-output build/pinyin_lexicon.canonical.tsv \
  --syllables-output ime-service/src/main/assets/pinyin_syllables.txt \
  --stats-output ime-service/src/main/lexicon/pinyin_lexicon.stats.json

The binary builder normalizes ü/u: to v, removes duplicate text/pinyin pairs,
caps each exact code at 128 candidates, and creates isolated prefix, initials,
and bounded hybrid indexes. Prefix and hybrid materialization is restricted to
manifest-selected frequency bands so richer exact coverage does not multiply
APK size or build time without bound.

The pinned build accepts 610,421 source rows and produces:

- exact: 524,851 keys, 610,298 candidates;
- statistical prefix: 9,310 keys, 71,510 candidates;
- initials: 76,017 keys, 188,151 candidates;
- hybrid: 213,604 keys, 236,549 candidates;
- total: 823,782 keys, 35,069,585 bytes;
- unique exact text: 608,314;
- pinyin_lexicon.bin SHA-256:
  71258c3d1b4cade8693a13564ead0217a7e92068bbe554ecc806ae0f3a08e800;
- pinyin_syllables.txt SHA-256:
  3033c80d4bd20fdf4bf8378a6e89b51edbc9c68ab6737b3e9a8ec962f3546bf3.

Sense's six production-specific curated phrases are in
ime-service/src/main/lexicon/sense_custom.dict.tsv. Synthetic ordering records
from earlier milestones are isolated under
ime-service/src/test/fixtures/lexicon/legacy_m5_ranking.dict.tsv and do not
enter the production manifest or APK.

Derived Chinese bigram asset
----------------------------

tools/build_bigram_model.py reads only exact primary-tier records, keeps the
strongest occurrence of each text, accumulates adjacent Han-character evidence,
normalizes it into bounded scores, and writes the strongest 65,536 of 386,348
observed pairs. Statistical-prefix, initials, and hybrid index records do not
enter the model.

ime-service/src/main/assets/pinyin_bigrams.bin is 786,442 bytes with SHA-256:
9f37c162783e1ea1cfb59a321cc310d32d693ef8d88b332ca28b29933760fe5d.
It is distributed under GPL-3.0-only with the Chinese dictionary asset set.

unique lowercase ASCII words of 1-32 letters, permits only a and i among

Rime Wubi / Wubi86 dictionary
----------------------------------------
Sense includes a deterministically compiled Wubi86 dictionary from Rime Wubi,
revision 152a0d3f3efe40cae216d1e3b338242446848d07.
The source dictionary is licensed under GNU LGPL v3.0. Sense excludes z-prefixed
symbol records and adds exact, completion and reverse indexes in its SWBX/1 format.
See licenses/RIME-WUBI-NOTICE.md and licenses/rime-wubi-LGPL-3.0.txt.
